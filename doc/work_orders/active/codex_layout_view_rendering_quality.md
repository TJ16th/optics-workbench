# Layout View 描画品質改善 指示書（Codex向け）

## 背景

曲率描画・光線屈折の修正が完了し、複数面（P003：S1/S2/S3）を持つ系で実際にブラウザ確認したところ、以下3点の描画品質課題が見つかった。光線本数や面数が増えるほど悪化する性質のため、Phase 3受け入れ確認（P3-6）より前に対応する。

## 課題1：光線の線が太く、複雑な系で輻輳して潰れる

現状、光線経路のSVG線が太め・不透明で、複数面・複数光線が交差すると視認性が大きく落ちる。

### 対応

1. 光線経路の線幅を細く（例：現状の半分程度）し、半透明（例：opacity 0.5〜0.7程度）にして、重なった箇所でも下の線が透けて見えるようにする。
2. Layout Viewで表示する光線本数を、Preview/Layout用途では意図的に絞る（fan_y方向の代表数本＋主光線程度。詳細なスポット分布は別途spot diagramチャートの役割とし、Layout Viewに全光線を詰め込まない）。P3-2〜P3-5のドラッグ中previewが`samples_per_field=5`程度に絞っていたにも関わらず今回の画面が輻輳して見えた原因を確認し、実際に送られている光線本数と描画本数を報告する。
3. 波長ごとに色分けている場合、色と線幅・透明度のバランスを見直し、重なっても波長の違いが判別できることを確認する（UI仕様の波長色規約：F=青系、d/e=緑黄系、C=赤系、との整合を保つ）。

## 課題2：有効径境界ライン（面をつなぐ端面）が無い

現状、各光学面はY方向の弧としてのみ描画され、隣接する2つの面の弧をつなぐ端面線が無いため、「ガラスの塊」として視覚的に伝わりにくい。

**用語の注意**：ここで描くのは`semi_diameter_mm`（有効径）に基づく境界線であり、実際のレンズ製造上の外径（コバ径、mechanical diameter）ではない。エンジン仕様には現時点で製造外径を表す変数が存在しないため、本タスクでは「有効径の位置で面同士を結ぶ」表現に留める。完了報告・UI上のラベル・コード内コメントで「外径」という語を使わず、「有効径境界」「clear aperture boundary」等、有効径由来であることが分かる表現を使うこと。

### 対応

1. 同一の光学要素（連続するrefractive面のペア、またはthickness_after_mm=0で連結された面等）について、両面の弧を端面で結び閉じた形状として描画する。境界線の位置は各面の Y = ±semi_diameter_mm（**半径**であることに注意。UI表示ラベルはglossaryの「有効半径」を使う）。この線は有効半径由来の境界であり、製造外径ではない。
2. **隣接面の有効半径が異なる場合の規約【自己検証で発覚した未定義事項】**：光学レイアウト図の慣例に従い、有効半径が小さい方の面を、その縁のsag X座標のままY方向に平坦延長し、大きい方の有効半径の高さ（Y = ±max(semiD_a, semiD_b)）で両面を結ぶ（squared edge方式）。実装が複雑になる場合は、両弧の端点を直線で結ぶ簡易方式でもMVPとして許容するが、どちらを採ったかを報告する。
3. **エッジ厚がゼロ以下（両面の弧が交差する）場合の挙動**：クラッシュ・描画スキップせず、交差したままの形状を描画する。あわせて該当要素を警告色でハイライトする（10.3節のvalidation警告「有効径の干渉」と整合する表現）。Surface Table編集中に一時的にこの状態になることは正常な操作過程であるため、描画が壊れないことをテストで固定する。
4. 空気で隔てられた面同士（air gapがある場合）は境界線で結ばない。ガラス材質で満たされた区間のみを閉じた形状として描画する。
5. 平面同士・平面と球面の組み合わせでも正しく外形が閉じることを確認する。

## 課題3：空気・単体ガラス・接合ガラスの区別がつかない

現状、すべての面が同じ色（青）で描かれ、単レンズが2枚並んでいるのか、接合レンズ（cemented doublet、面間の空気間隔が実質ゼロでガラス同士が貼り合わされている）なのかが視覚的に区別できない。

### 対応

1. 面と面の間の媒質（material_after）に応じて、塗りつぶし色・パターンを変える：
   - 空気（AIR）：塗りつぶしなし（透明）。
   - ガラス（各種硝材）：薄い色の塗りつぶし（硝材ごとに色を変える必要はないが、ガラスであることが分かる淡い塗りで統一。将来的に硝材ごとの色分けをしたい場合はIssue化する）。
2. 接合レンズの判定：隣接する2つの屈折面の間のthickness_after_mmが実質ゼロに近い、またはair gapが無くガラスからガラスへ直接接続している場合、その境界線を単体ガラス外周よりも細い/薄い線で描画し、「1つの接合ブロック」として視覚的にまとまって見えるようにする。単体レンズ同士の空気間隔がある境界とは明確に描き分ける。
3. ミラー・薄レンズ・センサー・眼基準面など、ガラスでない要素は従来通りの表現（17章規約）を維持し、今回の変更で崩れていないか確認する。

## 完了条件

- P003（現在S1/S2/S3の3面構成）で、線が細く半透明になり、複数光線が交差しても視認性が保たれることをスクリーンショットで確認する。
- 有効径境界ラインが表示され、ガラスの塊として視覚的にまとまって見える（製造外径ではなく有効径ベースであることが分かる形で）。
- 空気区間とガラス区間、可能であれば接合レンズ区間が塗りつぶし・線種で区別できる。
- 既存のE2E（layout view関連）が壊れていないこと、または描画方式変更に応じて更新されていることを確認する。
- 修正前後のスクリーンショット比較を報告する。

## 参考：判断に迷う場合

- 接合レンズの厳密な判定ロジック（thickness_after_mmの閾値等）が複雑になりすぎる場合、まずは「空気 vs ガラス」の区別だけを確実に実装し、「単体 vs 接合」の区別は簡易版（例えば閾値0.01mm未満は接合とみなす等、粗い判定でよい）で構わない。過剰に作り込まず、視覚的に破綻しない範囲でシンプルに実装する。

## 仕様正誤・仕様への反映【自己検証で発覚】

### エンジン仕様10.3節の曖昧さ修正（1行の正誤）

`doc/engine_spec.md` 10.3節のエッジ厚の定義「両面の共通有効径位置で評価」は、有効半径が異なる2面のどこで評価するかが曖昧である。以下のように修正する：

- 修正前：「隣接面間の周縁厚（頂点間隔にsag差を加味し、両面の共通有効径位置で評価）」
- 修正後：「隣接面間の周縁厚（頂点間隔にsag差を加味し、**両面の有効半径の小さい方 min(semiD_a, semiD_b) の位置**で評価）」

エンジン実装側にedge_thickness計算が既に存在する場合、実装がこの定義（min側で評価）と一致しているか確認し、報告する。

### UI仕様17章への描画規約の反映

本タスクで確定する描画規約（光線の線幅・透明度、ガラス塗りつぶし、境界線規則、有効半径が異なる場合のsquared edge、負エッジ厚時の挙動、接合レンズの簡易判定閾値）は、work orderにのみ存在すると仕様ドリフトの原因になる。本タスクの完了時に、`doc/ui_spec.md` 17章（可視化コンポーネント表示規約）へ、実装した規約を反映する（v0.3のまま17章への追記とし、追記箇所に【描画規約追記】と明記する。改訂履歴にも1行追加する）。

## Issueバックログへの追記依頼

本タスクの範囲外だが、以下を`doc/reports/issues_backlog.md`にIssue草案として追記する（AGENTS.mdのGitHub Issue運用節のフォーマットに従う）。

- タイトル：`面ごとの製造外径（mechanical_diameter_mm）を導入し、段付き外径をUIで表現できるようにする`
- ラベル案：`engine`, `ui`
- 背景：現在エンジンには有効径（`semi_diameter_mm`）のみが存在し、実際のレンズ製造上の外径（コバ径）を表す変数がない。R1・R2で有効径が異なる場合、実務では段付き外径研削で製造することが多いが、現状はこれを表現・計算できない。エンジン仕様v2.2で定義済みの`edge_thickness`評価値（10.3節・25.2節）は隣接面間の周縁厚み制約チェックに留まり、外径自体を決定する仕組みではない。
- 対応案：
  - 各面に任意の`mechanical_diameter_mm`を持たせる。**省略時は`semi_diameter_mm`と同値とする**（マージンの自動付与はしない。既定挙動を現行描画と同一に保つため）。マージンが欲しい場合はユーザーが明示的に値を指定する。
  - `mechanical_diameter_mm`は**描画・製造制約評価専用**であり、光線の遮光判定（エンジン仕様17.3節：semi_diameter_mmによる判定）には一切影響しない。この非影響をテストで固定する。
  - UIのLayout Viewで、面ごとに異なる`mechanical_diameter_mm`がある場合、段差のある外径として描画する。
  - edge_thicknessの評価位置は現行どおり有効半径基準（min側）を維持するが、将来的にmechanical edge位置での評価オプションを追加する余地を注記する。
  - 将来的な発展として、最小コバ厚み制約から外径を逆算する、外径差が過大な場合に警告するといった機能も検討課題として残す（本Issueでは対象外、必要なら別Issueに分割する）。
- 受け入れ条件：
  - `mechanical_diameter_mm`を面ごとに指定でき、省略時は有効径ベースの既定値が使われる。
  - UIが段付き外径を正しく描画する。
  - 既存の`edge_thickness`評価・validationと矛盾しない。
