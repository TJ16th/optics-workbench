# Optics Workbench UI Phase 3 作業指示書（Codex向け・タスクP3-0〜P3-6）

## 背景

UI Phase 1・Phase 2（i18n/ヘルプ含む）は実装済み。本指示書はUI仕様v0.3 29章の**Phase 3（群編集・スライダー操作・decenter/tilt操作UI）**を実装する。

Phase 1で既に実現しているもの：Surface Tableでの数値編集、Optical Layout Viewでのレンズ断面・光線経路・各面屈折点の静的表示。
Phase 3で新たに実現するもの：群位置（ズーム・フォーカス）・絞り径・decenter・tiltを**スライダーで連続操作し、Layout Viewと光線経路がほぼリアルタイムに追従する**体験。これはソフトの第一目的（教育用途、「操作に対してすぐ反応すること」）の中核機能である。

仕様の根拠：UI仕様v0.3 12章（光学系編集UI詳細仕様）、11章（Dirty State/Validation/Register規約）、17章（可視化コンポーネント表示規約）。エンジン仕様v2.3 の `POST /v1/education/preview`（26.5節）、群・ズーム/フォーカス位置（10章）、シフト・チルト（11章）、11.4節（非対称系の扱い・±field自動評価）。

## 進め方・恒常DoD

タスクは番号順に1タスクずつ、完了報告後に停止する。1タスク1コミット。AGENTS.mdの恒常DoD（新規文字列はi18nリソース経由、新metric/コードはglossary ja/en追記セット、Toggletip付与、scattergl使用、決定論・capabilities誠実性の維持）を全タスクに適用する。

## 前提確認

着手前に、現在のプリセット（P001〜P006）のうち、ズーム・フォーカス群、decenter、tiltを持つものがあるか確認する。無ければP3-0でプリセットを1つ拡張する。

## タスクP3-0：群操作対応プリセットの確認・追加

### 作業

1. `doc/ui_spec.md` 9章のP001〜P006を確認し、`groups`（ズーム/フォーカス/OIS等）・`decenters`・`tilts`を持つプリセットがあるか調べる。
2. 無ければ、既存プリセットのいずれか（ズームレンズが自然なP002やP004候補）に、フォーカス群1つ・手ブレ補正群（decenter対象）1つを追加した拡張版を作る。近軸トレースで像面が破綻しないことを確認する（9.1節の数値検証規約に従う）。
3. 拡張したプリセットの近軸検証結果を完了報告に含める。

### 完了条件

- 群・decenter・tilt操作を試せるプリセットが最低1つ用意されている。
- 近軸検証結果（EFL、BFL等）が報告されている。

---

## タスクP3-1：群定義の表示・編集UI

### 作業

1. 光学系編集UIに「Groups」パネルを追加する：群ID・名前・from_surface/to_surfaceの表示、群の新規作成・削除・範囲編集。
2. 群範囲編集はSurface Tableとの整合を取る（存在しないsurface_idを範囲に含められない、範囲の重複を警告する等）。
3. 編集はconfiguration_dirtyまたはsystem_dirty（群の新規作成/削除は構造変更なのでsystem_dirty）に正しく連動させる（11章のdirty規約）。

### 完了条件

- 群の作成・編集・削除がSurface Tableと整合した状態でできる。
- dirty遷移のテスト。

---

## タスクP3-2：ズーム・フォーカス位置のスライダー操作

### 作業

1. `zoom_positions`が定義されている場合、ズーム位置を離散選択（wide/tele等）またはその間を補間する連続スライダーで操作できるUIを実装する。
2. フォーカス群のX方向シフトを連続スライダーで操作できるUIを実装する（`{group_id}_shift_x_mm`をruntime configurationとして送信）。
3. スライダードラッグ中は `POST /v1/education/preview`（aiming: paraxial、少数光線）を**デバウンス**して呼び出し、Layout Viewと光線経路を追従させる。ドラッグ終了時（mouseup等）に、必要であれば通常解像度のanalysisへ切り替えて結果パネルを更新する。
4. リクエスト頻度・デバウンス間隔は、体感遅延とAPI負荷のバランスを見て決定し、採用値と理由を完了報告に記載する。

### 完了条件

- スライダー操作でLayout View・光線経路が追従して更新される。
- ドラッグ終了時に高解像度側の結果へ切り替わる。
- P3-0のプリセットでズーム/フォーカス操作のスクリーンショットまたは動作ログを報告する。

---

## タスクP3-3：絞り径スライダーとの統合

### 作業

1. 既存のiris_radius_mm編集（Phase 1で数値入力があれば）をスライダー化し、P3-2と同じpreview連携方式に統合する。
2. 絞りを絞ると光線束が変わる様子がLayout Viewでリアルタイムに見えることを確認する（エンジン仕様glossary `aperture_stop` の `lesson_mode: aperture_effect` に対応する体験）。

### 完了条件

- 絞りスライダー操作で光線束の変化がリアルタイムに見える。

---

## タスクP3-4：Decenter（シフト）・Tilt操作UI

### 作業

1. 光学系編集UIに「Decenter / Tilt」パネルを追加する：対象（面範囲または群）選択、shift_y_mm/shift_z_mm、tilt_y_deg/tilt_z_deg/roll_x_deg、rotation_center設定の編集。
2. シフト・チルト量もスライダー（微小レンジ、例：±5mm、±5deg）で操作でき、P3-2と同じpreview連携方式で追従する。
3. decenter/tiltが非ゼロになった場合、エンジンが自動的に±field評価へ切り替える（仕様11.4節）。UIは応答metadataの実評価field一覧を表示する（P2-1で実装済みの仕組みを利用）。
4. Layout Viewで、シフト・チルトされた面・群を視覚的に区別する（オフセット表示、傾き表示）。17章の可視化規約に従う。

### 完了条件

- decenter/tilt操作で光学系が非対称に変化し、Layout Viewに反映される。
- ±field評価への自動切り替えがUI上で分かる。

---

## タスクP3-5：レスポンシブネス確認と既知の制約報告

### 作業

1. P3-2〜P3-4のスライダー操作について、体感遅延を計測する（性能改善work orderの計測方法を流用してよい）。
2. エンジン側の性能改善（タスク0〜7）が未完了の場合、education previewのレイテンシが仕様目標（50〜100ms）に届いていない可能性がある。その場合は「UIの実装は完了しているが、エンジン側の性能改善待ちで体感が重い」ことを明確に区別して報告する（UI側の不具合と混同しない）。
3. 現状のレイテンシと、目標達成に必要なエンジン側タスクへの参照を完了報告に含める。

### 完了条件

- レイテンシ計測結果が報告されている。
- UI起因かエンジン起因かの切り分けが報告されている。
