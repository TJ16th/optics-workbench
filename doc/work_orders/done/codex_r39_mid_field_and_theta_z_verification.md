# R37推奨fieldの数値検証：mid角度の算出根拠とtheta_z固定の妥当性確認 指示書（Codex向け）

## 背景

人間がR37完了後の実際の値（例：edge=18deg, mid=10deg, center=0deg）を確認したところ、2点の疑問が生じた。

1. `mid`が本当に「edgeの70%（画角ベース）」または「像高の70%（像高ベース）」で計算されているか。edge=18degなら画角ベースの70%は12.6degになるはずだが、実際は10degであり、単純な数値検証で不一致に見える。
2. `theta_z_deg`が全プリセットで常にゼロになっている。エンジン仕様の4.3節（field角度の方向ベクトル合成規約）はtheta_y・theta_z両方の指定を前提としており、Z方向（面内垂直）の画角が一切表現されていない状態が意図的な設計か、実装上の見落としかを確認する必要がある。

## 作業

### 1. mid角度の算出根拠確認

1. R37で実装した`mid` field角度の算出コードを確認し、実際に使われている計算式を明記する。
2. 現在の値（例：edge=18deg時にmid=10deg）が、その計算式からどう導かれたか、実際に数値を代入して検算する。
3. もし「画角ベース70%」「像高ベース70%」のどちらでもない値（例えば固定の中間値、または別の丸め処理）になっている場合、その理由を報告する。
4. R38の目的（7割像高field）に照らして、現在の`mid`値が妥当かどうかを判断する。妥当でなければ、正しい計算式（画角ベースまたは像高ベース、どちらを採用するかも明記）に修正する。

### 2. theta_z固定の妥当性確認

1. R37で実装したプリセット推奨fieldが、なぜ`theta_z_deg`を常にゼロにしているか、実装意図を確認する（明示的な設計判断か、単に実装時に考慮されていなかったか）。
2. エンジン仕様4.3節・11.4節（非対称系の扱い）を踏まえ、Y方向のみで代表させることが問題にならないケースと、問題になりうるケース（decenter/tilt込みのプリセット、P003拡張版等）を整理する。
3. 対応方針を判断し報告する：
   - (a) 現状維持（theta_yのみで代表、理由を明記）。
   - (b) 非対称性のあるプリセット（P003等）では、theta_zにも意味のある値を設定する。
   - (c) 両軸に振ったfieldセット（例：+Y、-Y、+Z、-Zの4点等）に拡張する。
   - 判断に迷う場合は、過剰実装を避けつつ、最低限「なぜtheta_zがゼロなのか」をコード上のコメントまたは仕様書に明記する。

## 完了条件

- mid角度の算出根拠が数値検証込みで報告されている。不一致があれば修正されている。
- theta_z固定の理由が明確化され、対応方針（a/b/cのいずれか）が実施または理由付きで見送られている。
- 既存テストがグリーン、必要な新規テストが追加されている。
- 完了報告前にプロセスを再起動し、`build_info.git_commit`がHEADと一致することを確認し、断定形で報告に記載する（未来形で締めない）。

本タスクの結果を踏まえて、R38（7割像高）の内容を最終確定させる。
