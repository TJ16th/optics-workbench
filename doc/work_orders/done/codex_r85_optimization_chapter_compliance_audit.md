# R85：engine_spec.md 25章（最適化API）仕様準拠監査 指示書（Codex向け）

## この指示書の性質

**本タスクは監査（現状把握）のみを目的とし、設計提案・実装は行わない。** R84でCodexが実コードを調査した結果、`doc/engine_spec.md` 25章の一部（25.3節の残差ベクトル、25.5節のray_loss_ratioペナルティ、25.6節の変数キー体系）が、仕様書の記載と実際のコードとの間で無視できないギャップを持つことが偶然判明した。人間から「他にも同種の気になる点がないか、Codexに仕様チェックさせてみたい」との要望があり、対象を25章全体に確定した。

R84で個別に見つかったギャップは、あくまでヤコビアンバッチモード（25.7節）の設計検討の副産物だった。本タスクは、25章全体を体系的に一節ずつ点検し、「仕様書に書かれていることが実際にどの程度実装されているか」を一覧化することを目的とする。

## 作業

### 1. 節ごとの実装状況確認

`doc/engine_spec.md`の以下の各節について、記載されている契約・データ構造・アルゴリズムが、現行コードで①完全実装②部分実装③未実装のいずれかを、実コード確認（該当ファイル・関数名を明記）とAPI直接呼び出しの両方で判定する。

- 25.1 方針（外部最適化アルゴリズムとの境界線）
- 25.2 評価値（評価値metric一覧）
- 25.3 オペランドと残差（オペランド定義・残差ベクトル正規化）
- 25.4 Merit Function（残差二乗和＋ペナルティとしてのmerit定義）
- 25.5 光線破綻の連続ペナルティと決定論（ray_loss_ratio疑似オペランド、merit再現性規約）
- 25.6 最適化変数の空間とキー体系（curvature空間推奨、conic・非球面係数・群位置の変数化キー）
- 25.7 ヤコビアンバッチモード（R84で未実装と確認済み、本タスクでは再確認のみでよい）
- 25.8 将来の勾配提供（自動微分、将来拡張として明記されているものが、誤って「現在実装済み」と読める記述になっていないかの確認のみ）

### 2. 関連節の確認

25章の改訂と同時に追加されたと`doc/engine_spec.md`冒頭の変更履歴に記載されている、以下の関連節も対象に含める。

- 10.3節・25.2節（edge_thicknessオペランド）
- 26.3節・26.6節（近軸像距離solve）
- 15.3節（gaussian_quadrature瞳サンプリング）

### 3. ギャップの分類・優先度付け

見つかったギャップそれぞれについて、次を明記する。

- 完全未実装／部分実装（部分実装の場合は何が実装済みで何が欠けているか）
- 単なる文書の記載漏れ・表現の古さなのか、実際にコードとして必要な機能が欠けているのかの区別
- O8-13（最適化タスク8〜13）着手にとって、必須の前提（ブロッカー）なのか、軽微・後回し可能なのかの評価
- 判明している場合は、関連する既存のissues_backlog.md項目・過去のR番号タスクとの重複有無

### 4. 一覧化

全節の判定結果を一つの表にまとめる。列は「節番号／節タイトル／実装状況（完全・部分・未実装）／根拠（ファイル・関数・API確認結果）／ギャップの内容／O8-13へのブロッカー度（高・中・低）」とする。

- 各ギャップについて、文書記載漏れか実装欠落かの区別、O8-13へのブロッカー度評価が明記されている。

- 見つかったギャップの修正・実装は本タスクの対象外。次のステップ（修正方針の検討・発注）はこの監査結果を踏まえて人間とClaudeが判断する。
