# R62：プリセットのサンプル網羅性の穴を埋める 指示書（Codex向け）

## 背景

人間・私（Claude）で、現行プリセット（P001〜P007）のサンプル網羅性を確認したところ、3つの穴が見つかった。

1. **P007のドキュメント欠落**：P007（F1.4正負2枚組）は実際に稼働しているプリセットだが、`doc/ui_spec.md` 9.4節（プリセット一覧）に一度も記載されていない。同9.1節の「代表的な光学系を6つ内蔵する」という記述も、実際には7つになっているため古い。
2. **実レンズ構成のアフォーカル系プリセットが無い**：アフォーカル系のプリセットはP006（Keplerian Telescope 10x Afocal Demo）のみだが、`kind: thin_lens`（理想薄レンズ、f=200mm対物・f=20mm接眼）だけで構成されており、実ガラス・実曲率の屈折面（`kind: refractive`, `surface_type: spherical`, 実際の`N-BK7`等）が1枚も使われていない。P002〜P004のような実レンズの色収差・球面収差が、アフォーカル評価（角度spot、angular MTF等）でどう見えるかを確認する手段が現状ない。
3. **非球面を使った正式プリセットが無い**：非球面（`asphere_coefficients`使用）は、`?fixture=asphere-layout`という隠しURLパラメータの開発用fixture（`doc/reports/2026-07-09_ui_phase3_followup2_asphere.md`）にしか存在せず、通常のプリセット一覧からは選べない。engine_spec.mdが目的として掲げる「非球面が球面収差をどう補正するか」（1.4節相当）を、通常のUI操作だけでは確認できない。

## 作業

### 1. P007のドキュメント整合（軽量修正）

1. 実際に稼働しているP007の面構成（`apps/workbench-ui/src/domain/presets.ts`等の実データ）を確認する。
2. `doc/ui_spec.md` 9.4節に、P001〜P006と同じ形式（目的・面テーブル・期待値）でP007の項を追加する。
3. 9.1節の「代表的な光学系を6つ内蔵する」を実際の数（本タスク完了後の総数）に更新する。
4. `doc/engine_spec.md`側にもプリセット一覧・言及があれば、整合させる（無ければ本タスクでは追加不要）。

### 2. 実レンズ構成のアフォーカル系プリセットを新設

1. 次のプリセット番号（P007の次、実際の最終番号をコードで確認してから決定すること。推測で数字を決めない）で、実ガラス・実曲率の屈折面で構成されたアフォーカル系プリセット（ケプラー式またはガリレオ式の望遠鏡・双眼鏡）を設計する。
   - 対物・接眼とも、単玉ではなく色収差補正されたダブレット（P003のアクロマートに準じる構成）を推奨するが、過度に複雑にせず「実レンズであること」が伝わる最小構成でよい。
   - `system_type: afocal`、終端要素`eye_reference`とする（engine_spec.md 9.2節に従う）。
2. `doc/ui_spec.md` 9.1節の数値検証規約に従い、実装前に近軸トレース（`/v1/analysis/paraxial`）で角倍率・射出瞳径・アイレリーフ等を検証し、代表fieldの実光線追跡で軸上・最外光束が各面でケラれないことを確認してから数値を凍結する。
3. 期待値（角倍率、射出瞳径、残存ディオプター等）をP006に準じた形式で報告書に明記する。
4. UIプリセット一覧・`doc/ui_spec.md` 9.4節にも追加する。

### 3. 非球面を使った正式プリセットを新設

1. 既存の非球面fixture（`?fixture=asphere-layout`）の構成を土台として使ってよいが、通常のプリセット一覧から選べる正式プリセットとして昇格・再設計する。
2. 目的は「非球面が球面収差をどう補正するか」を確認できることとする。例えば、P002相当の球面単玉と、同等の焦点距離・F値を持つ非球面単玉を比較できる構成（または1つのプリセット内で両者を切り替えられる構成）を検討する。どちらの設計にするかはCodexの判断でよいが、理由を報告に明記する。
3. `doc/ui_spec.md` 9.1節の数値検証規約に従い、近軸トレースと実光線追跡で検証してから数値を凍結する。spot diagramで球面版より非球面版の方が収差が小さいことを示せると理想的である。
4. UIプリセット一覧・`doc/ui_spec.md` 9.4節にも追加する。

## スコープ外

- 既存プリセット（P001〜P007）の数値変更は行わない。
- R61で保留と決めた反射系（P005/P006カセグレン・ケプラー式）関連の追加調査・変更は行わない。

## 完了条件

- P007がui_spec.md 9.4節に記載され、9.1節のプリセット数記述が実数と一致している。
- 実レンズ構成のアフォーカル系プリセットが追加され、近軸トレース・実光線追跡による検証結果（角倍率・射出瞳径・ケラレ有無）が報告書に数値で明記されている。
- 非球面を使った正式プリセットが追加され、同様に検証結果が数値で明記されている。可能であれば球面版との収差比較結果も示す。
- 新規プリセットがそれぞれ`doc/ui_spec.md` 9.4節に、既存プリセットと同じ形式で記載されている。
- 修正後のLayout View（またはSpot Diagram等の該当ビュー）のスクリーンショットが新規プリセットごとに`doc/reports/screenshots/`へ保存され、報告書から参照される。
- 既存テストがグリーン。新規プリセット追加に伴う回帰テスト（P0-7 タスク6以降で追加された`test_preset_api_smoke.py`的な、動的プリセット読み込みベースのテストがあれば、それが新規プリセットも自動的にカバーすることを確認する）。
- 完了報告前にプロセスを再起動し、`build_info.git_commit`がHEADと一致することを断定形で記載する（未来形で締めない）。
- **完了報告の実装根拠には、コミットメッセージだけでなく実際のコミットハッシュ値を必ず併記する。**

## 注意

- 作業1（ドキュメント整合）・作業2（アフォーカルプリセット）・作業3（非球面プリセット）は、それぞれ独立した内容なので、AGENTS.mdの通常規約（1タスクずつ・完了報告後に停止）に従い、作業ごとに区切って進めてよい。バッチ実行可とは明記しない（新規プリセットの数値検証は「やってみないと分からない」性質があるため）。
