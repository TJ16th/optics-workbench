# Issueバックログ一括登録（気になることリスト由来・大型機能候補） 指示書（Codex向け）

`doc/reports/issues_backlog.md`へ以下7件を追記する。**実装は行わない、登録のみ**。AGENTS.mdのGitHub Issue運用節のフォーマットに従う。

## 1. 撮影結果シミュレータ

- ラベル案：`engine`, `ui`
- 背景：現在の解析はPSF/MTF/spot等の光学評価値が中心。RGBD画像等を入力に、レンズの収差・被写界深度を反映した撮影結果をシミュレーションする機能は無い。
- 対応案：まず無収差・無限深度のRGBD画像に対し、PSFを畳み込む簡易シミュレーションから着手する。将来的に被写界深度（フォーカス位置とオブジェクト距離のズレによるボケ量）を反映する段階的拡張とする。
- 受け入れ条件：（初期段階）単一PSFでの画像畳み込みが動作する。

## 2. 太陽光5000K等の連続スペクトルでの色収差シミュレーション

- ラベル案：`engine`
- 背景：現在の色収差評価はF/d/C等の離散波長が中心。連続スペクトル光源（例：太陽光5000K）での軸上色・倍率色のリアルな表現には、`light_sources`のサンプル密度を上げるか、連続スペクトルモデルが必要。
- 対応案：既存の`light_sources`（波長サンプル＋重み）の仕組みを流用し、サンプル数を増やした高密度スペクトルプリセットを追加する。エンジン変更は最小限、プリセットデータの追加が中心となる可能性がある。
- 受け入れ条件：5000K相当のサンプルスペクトルで軸上色収差カーブが滑らかに評価できる。

## 3. 面反射ゴーストシミュレーション

- ラベル案：`engine`
- 背景：現在のトレースは単純透過経路のみ。反射ゴースト（面での部分反射により生じる迷光）は評価対象外。
- 対応案：仕様3.2節で「将来拡張」として明記済みの項目。多重反射経路の光線追跡（反射率を持つ面の扱い）を検討する。エンジンの基本設計（シーケンシャル追跡）を非シーケンシャルに近づける必要があり、大規模な拡張になる可能性がある。
- 受け入れ条件：（初期段階）2面反射までの単純なゴースト経路を計算できる。

## 4. コート特性・CCI（教育目的の項目）

- ラベル案：`engine`, `docs`
- 背景：コーティングの透過率・反射率特性は仕様16.5節・21.4節で「非対応」と明記されている。「コートを付けるとゴーストが減る」という教育的な説明のための簡易項目として追加したい。
- 対応案：詳細な多層膜計算ではなく、面ごとに反射率係数（定数または波長依存の簡易カーブ）を持たせ、上記3のゴーストシミュレーションと組み合わせて「コート有無でゴースト強度が変わる」ことを示す教育的な簡易モデルとする。
- 受け入れ条件：（初期段階）反射率係数の設定と、それがゴースト強度計算に反映されることを確認できる。

## 5. ズーム/フォーカス時の撮影シミュレーション（歪曲変化・ブリージング）

- ラベル案：`ui`
- 背景：ズーム・フォーカス位置を変えたときの歪曲変化やフォーカスブリージング（フォーカス移動に伴う画角変化）を、方眼チャート等を使って視覚的に示したい。
- 対応案：方眼チャート画像に歪曲マップを適用して表示する簡易版から着手する。ボケ表現は上記1の撮影結果シミュレータと連携する可能性がある。
- 受け入れ条件：（初期段階）方眼チャートが歪曲量に応じて変形して表示される。

## 6. 光学系の3Dデータ出力（3Dプリンタ用カットモデル）

- ラベル案：`ui`, `engine`
- 背景：レンズ形状を3Dプリンタで出力して手元で確認する用途。光学性能を持つ必要はなく、断面形状（カットモデル）としての出力で良い。多色FDM想定。
- 対応案：面のsagデータから回転体としての3D形状（STL等）を生成する。これは既存のLayout View（2D断面）の3D版に近く、有効径境界の考え方（Q1で実装済み）を再利用できる可能性がある。
- 受け入れ条件：単純な単玉・2枚玉プリセットからSTLファイルが出力できる。

## 7. 解析条件・表示設定のプリセット機能

- ラベル案：`ui`
- 背景：波長・光線数などの解析条件、Super35やフルフレーム等のセンサーサイズ設定を、決まった構成として呼び出したい。表示設定（チャート表示のオン/オフ等）のプリセットも欲しい。
- 対応案：解析条件プリセット（センサーサイズ・波長セット・光線数の組み合わせ）と、表示設定プリセット（どのチャートを表示するか等）を、それぞれ名前付きで保存・呼び出せるようにする。Snapshotの仕組み（22.4節）と一部重なるため、責務の違いを明確にした上で設計する。
- 受け入れ条件：数個の既定プリセット（Super35、フルフレーム等）が用意され、選択で解析条件が切り替わる。
