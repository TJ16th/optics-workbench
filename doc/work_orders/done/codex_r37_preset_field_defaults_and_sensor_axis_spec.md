# プリセットfield推奨値の導入とセンサーY/Z軸割当の仕様明記 指示書（Codex向け）

R36の調査結果を踏まえた実装タスク。2件をまとめて扱う（互いに独立しているためバッチ実行可）。

## 1. プリセットへのfield推奨値付与（R36②への対応）

### 背景

R36の調査で、プリセット切り替え時にfield角度がリセットされず、狭角プリセットに広角プリセット由来の角度が残留する具体的な不具合が確認された（例：P002選択後20度、P005へ切替後もtheta_z=20度が残留）。

R36が提示した3方針のうち、**(a) 各プリセットに推奨fieldセットを持たせ、プリセット切り替え時にその推奨値へリセットする**を採用する。理由：プリセットは教育・デモ目的であり、各プリセットの光学設計（画角・EFL等）に対して意味のあるfield（中心・周辺）を最初から見せることが、ソフトウェアの教育目的（仕様1.1節）に直結する。ユーザーが毎回手動調整する(b)案は、初見ユーザーへの体験を損なう。

### 作業

1. 各プリセット（P001〜P007）に、推奨field情報を追加する。近軸検証で使用した画角、またはそのプリセットの想定用途に応じた妥当なfieldセット（中心・中間・周辺の3点程度が目安、afocal系のP006は角度の基準が異なる可能性があるため個別に検討する）を設定する。
2. プリセット切り替え時、解析条件のfieldをこの推奨値へ自動的にリセットする。ユーザーが手動で変更したfieldは、同一プリセットを選択している間は保持する（切り替えた瞬間だけリセットする）。
3. リセットが行われたことをユーザーに分かる形で示す（軽微な通知、またはfield欄の値が変わったことが視覚的にわかれば十分。過剰な演出は不要）。
4. 既存のE2E（field編集関連）が壊れていないか確認し、プリセット切り替え時のリセット動作を確認するテストを追加する。

## 2. センサーY/Z軸割当の仕様明記（R36③への対応）

### 背景

R36の調査で、`sensor.width_mm`=Y軸・`sensor.height_mm`=Z軸という規約が実装上は一貫して使われているが、`doc/engine_spec.md`にこの対応関係が明記されていないことが判明した。

### 作業

1. `doc/engine_spec.md`の6.5節（センサー）に、以下を明記する：
   ```text
   width_mm はY軸方向（面内水平）、height_mm はZ軸方向（面内垂直）に対応する。
   ```
2. `doc/ui_spec.md`側にも、対応する記述が必要であれば追記する（センサー編集UIの説明箇所等）。
3. 改訂履歴に1行追加する。

## 完了条件

- P001〜P007それぞれに推奨fieldが設定され、プリセット切り替え時に自動リセットされる。
- 手動変更したfieldが、同一プリセット内では保持される。
- `doc/engine_spec.md`にセンサーY/Z軸割当が明記されている。
- 既存テスト・E2Eがグリーン、新規テストが追加されている。
- 完了報告前にプロセスを再起動し、`build_info.git_commit`がHEADと一致することを確認し、断定形で報告に記載する（未来形で締めない）。
