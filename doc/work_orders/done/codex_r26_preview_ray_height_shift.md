# プレビュー光線：光線数変更時の絞り通過高さのズレ確認 指示書（Codex向け）

## 背景

人間からP002での動作確認により、「光線数を変えるとプレビューの光束の位置がずれて見える。絞りを通る光線の高さが変わって見える」という指摘があった。

Q4（光線数変更時の挙動検証）では、`samples_per_field`変更時にfields/pupil_distribution/aiming.modeが意図せず連動していないことを確認済みで、「見た目の変化は密度増加による自然な変化」と結論づけていた。しかし今回の指摘は、密度の変化ではなく**特定の代表光線（LOD表示対象）の絞り通過高さそのものが、光線数を変えるとズレる**という、より具体的な内容である。

Q1-symmetry（LOD光線サンプリングの対称性欠如修正）で、LayoutViewの代表光線選択を「sample indexベース」から「実際のSTOP位置Yに基づくlower/center/upper選択」に変更した経緯があり、この選択ロジックが光線数（samples_per_field）を変えたときに一貫した基準点を選べているか、という点が今回の疑いの中心になる。

## 作業

1. P002で、光線数（`samples_per_field`）を複数パターン（例：5, 9, 15, 25）に変えたときの、実際のLayout View表示光線（`lower/center/upper`等のLOD代表）について、それぞれのSTOP面到達Y座標を記録する。
2. 記録した座標を比較し、光線数を変えても「lower」「center」「upper」が指し示す物理的な瞳位置（例えば「絞り半径の何%の高さか」）が一貫しているか確認する。
   - 一貫していれば、見た目のズレは瞳サンプリング密度自体の変化（サンプル数が変わればhexapolar等の分布パターンが変わり、結果的に最外殻のサンプル半径・角度分布が変化する）による自然な現象である可能性が高い。この場合、その旨を報告し、必要であれば人間に分かりやすい説明（「本数を増やすと最外周のサンプル半径が変わることがある」等）をUI上のツールチップやヘルプに追記するか検討する。
   - 一貫していなければ、LOD代表選択ロジック（Q1-symmetryで実装した`lower/center/upper`選択）に光線数依存のバグがある。原因を特定し修正する。
3. `pupil_distribution`（hexapolar等）の仕様上の性質として、サンプル数を変えると最外周・最内周のリング半径自体が変わりうるか、エンジン仕様20章を確認する。もしそうであれば、これは「LOD選択のバグ」ではなく「瞳サンプリング方式そのものの仕様上の性質」であり、Q4の結論（自然な変化）を補強する形になる。
4. 上記のいずれであるかを明確に切り分けて報告する。

## 完了条件

- P002での光線数変更時のSTOP到達Y座標比較データが報告されている。
- 「LOD選択ロジックのバグ」か「瞳サンプリング方式の仕様上の性質」かが明確に切り分けられている。
- バグであれば修正され、テストで固定されている。
- 仕様上の性質であれば、人間にとって分かりやすい説明が検討・追記されている。
