# R45：主鏡M1の中央開口が描画されない／副鏡M2が依然として過大サイズ 調査 指示書（Codex向け）

## 背景

R44完了後、人間が実際にブラウザで確認したところ、まだ2点の問題が残っている。

1. **主鏡M1に中央開口（穴）が描かれていない**：R42の③で「annulus絞りは主鏡M1の中央開口を表現している」と結論づけ、R44でSTOP位置をM1側に修正したが、実際の描画ではM1が連続した弧（穴なし）のままである。R42の完了条件に含まれていた「M1の描画に穴を反映する」対応が、実装されていない可能性が高い。
2. **副鏡M2が依然として過大に描かれている**：R42の⑤で「副鏡M2の`semi_diameter_mm`とannulusの`inner_semi_diameter_mm`を一致させ、M2の描画をその径に収める」対応をしたはずだが、実際の描画ではM2が画面上下いっぱいの大きなサイズで表示されており、annulusのinner半径（画面中央付近に見える小さな範囲）と比べて明らかに不釣り合いである。

これはR42の完了報告と実際の表示が食い違っていた（R43/R44で発覚した問題）のと同じパターンの再発である可能性が高い。**今回は特に、実際にブラウザのスクリーンショットで確認しながら作業を進めること。**

## 作業

### 1. 現状の客観的な確認（最優先）

1. P005のsystem定義における、M2の`semi_diameter_mm`と、annulus STOP面の`inner_semi_diameter_mm`・`outer_semi_diameter_mm`の実際の値を確認する。
2. R42で「一致させた」と報告された値が、現在のsystem定義に実際に反映されているか確認する（R44の作業でSTOP位置を変更した際に、誤って古い値に戻っていないか、または別の値で上書きされていないか確認する）。
3. Layout View描画コードで、M2の弧を描く際に使用している半径の値が、system定義の`semi_diameter_mm`を正しく参照しているか確認する（ハードコードされた値や、別の変数を参照していないか確認する）。
4. M1の描画コードを確認し、中央開口（穴）を表現する処理が実装されているか、されていなければその理由を確認する（R42で「検討する」に留まり実装されなかった可能性を含む）。

### 2. 副鏡M2のサイズ修正

1. 作業1の確認結果を踏まえ、M2の描画サイズが正しく`semi_diameter_mm`（annulusのinner半径と一致しているべき値）を反映するよう修正する。
2. 修正後、実際にブラウザで確認し、M2がSTOP（annulusのinner半径）と整合する小さいサイズで描画されることをスクリーンショットで確認する。

### 3. 主鏡M1の中央開口の実装

1. M1の弧描画に、annulusのinner半径に相当する中央部分の欠け（穴）を反映する。過剰な作り込みは避け、M1の弧を上下2つの円弧セグメントに分割し、中央（inner半径の範囲）を描画しないシンプルな対応でよい。
2. 修正後、実際にブラウザで確認し、M1に中央開口が視覚的に確認できることをスクリーンショットで確認する。

### 4. 最終確認

1. P005のLayout Viewで、以下がすべて同時に成立していることを、実際のスクリーンショットで確認する：
   - M1に中央開口がある。
   - M2はannulusのinner半径と一致する小さいサイズで描かれている。
   - STOPマーカーの位置がM1側にある（R44で修正済みのはず、変化していないことを確認）。
   - 光線がSTOP/annulusで中央遮蔽されている。
2. 他のプリセット（P001〜P004、P006、P007）のLayout View描画に、本タスクの修正が悪影響を与えていないか確認する。

## 完了条件

- M2がannulusのinner半径と一致するサイズで描画される。
- 上記2点が実際のスクリーンショットで確認され、**`doc/reports/screenshots/2026-07-11_r45_m1_hole_and_m2_size_1.png`（複数枚なら_2, _3...）としてリポジトリに保存し**、完了報告書からそのファイルへの相対パスで参照する形で添付されている。
