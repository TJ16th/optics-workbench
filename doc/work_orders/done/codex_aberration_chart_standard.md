# 解析チャート：軸ラベル崩れの修正と縦収差図（業界標準3パネル）への準拠 指示書（Codex向け）

## 着手タイミング

Layout View描画品質改善・光線数挙動検証の完了後に着手する（それまでは着手しない）。

## 背景

人間から2点のフィードバックがあった。

1. 解析チャートの軸ラベルが重なる等、表示が崩れて見える箇所がある。
2. 現在のチャート構成が、光学業界で標準的な「縦収差図」（球面収差・非点収差・歪曲収差の3パネル表示）と比べて見慣れない・不足している印象がある。参考：https://www.photo-china.net/sinsaku/syusa.html

## 参考資料の要点（業界標準「縦収差図」）

3パネル横並びで、**縦軸は共通して半画角（deg）または像高**、横軸は各パネルで異なる：

| パネル | 横軸 | 縦軸 | 内容 |
|---|---|---|---|
| 球面収差図 | デフォーカス量（mm） | 瞳座標（0〜1.00、周辺光線ほど外側） | 軸上fieldにおいて、瞳位置ごとの焦点ズレ。複数波長を色分けして重ね描き。ゼロ位置が基準像面。 |
| 非点収差図（像面湾曲） | 像面ズレ量（mm） | 半画角（deg、0〜最大画角） | 各fieldでのT（タンジェンシャル/メリディオナル、破線）とS（サジタル、実線）の像面位置。2本の線が0度から離れるほど開くのが典型。 |
| 歪曲収差図 | 歪曲率（%） | 半画角（deg） | 各fieldでの歪曲率。 |

この3パネル構成は、エンジン仕様の`longitudinal_aberration`（球面収差図に相当）、`ms_image_surface`（非点収差図のT/Sデータに相当）、`distortion`（歪曲収差図に相当）の3エンドポイントに対応する。

## 作業

### 1. 軸ラベル崩れの調査・修正

1. 現在崩れて見えるチャート（複数箇所ある可能性がある）を特定し、原因を確認する（ラベル文字列が長い、チャート幅に対してフォントサイズが合っていない、自動レイアウトの計算ミス等）。目視だけでなく、該当チャートのSVG/DOM構造を確認して原因を特定する。
2. P002・P003それぞれの全解析チャート（ray fan, distortion, field curvature, relative illumination, MTF等、Phase 2で実装済みのもの）を表示し、崩れがないか横断確認する。
3. 修正する。

### 2. 縦収差図3パネル表示への準拠確認・改修

1. 現在のチャート実装が、上記3パネルの内容・軸の取り方とどう違うかを確認する（差分を報告する）。
2. 差分がある場合、以下いずれかの方針で改修する（判断して報告する。過剰改修は避ける）：
   - (a) 既存の`longitudinal_aberration`・`field_curvature`（またはms_image_surface）・`distortion`チャートを、業界標準の軸配置（縦軸=半画角、横軸=収差量、球面収差図のみ縦軸=瞳座標）に合わせて描き直す。
   - (b) 3つを1つの「縦収差図」パネルとして横並びに配置するビューを新設し、既存の個別チャートは維持する（両方使えるようにする）。
3. 波長ごとの色分け（既存の波長色規約：F=青系、d/e=緑黄系、C=赤系）を球面収差図に適用する。
4. 非点収差図でT（破線）/S（実線）の線種を区別する。
5. P003（アクロマートダブレット、色収差確認用プリセット）で実際に表示し、参考資料にあるような巻き型/直立型の球面収差カーブの違いが視覚的に判別できるかを確認する。

## 完了条件

- 軸ラベル崩れが解消されている（P002・P003全チャートで確認）。
- 縦収差図3パネル（またはそれに準じる表示）が、業界標準の軸配置で表示される。
- 既存チャートとの関係（置き換えか併存か）が報告されている。
- 完了報告前にプロセスを再起動し、`build_info.git_commit`がHEADと一致することを確認する（AGENTS.md規約通り）。

## 判断に迷う場合

3パネルの完全な統合ビュー構築が大きすぎる場合、まず(a)の軸配置修正のみを先に行い、統合レイアウトは別タスク・Issueとして`doc/reports/issues_backlog.md`に切り出してよい。その場合はその旨を報告する。
