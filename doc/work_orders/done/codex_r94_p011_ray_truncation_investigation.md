# R94：P011 Layout Viewで光線が途中で切れて見える件の調査 指示書（Codex向け）

## 背景

人間がPreviewタブでP011（Planar型6枚ダブルガウス）のLayout Viewを見て、軸外（周辺field）の破線光線が像面（IMG）まで到達せず途中で切れているように見える、と指摘した。

P011には既知の未修正backlog項目がある：R67導入時から、`3 fields × 3 wavelengths × 25 rays`・`hexapolar`・`full aiming`条件で`alive 213 / aiming_failed 12 / blocked 0`となることが確認されており（開口による遮光ではなく、周辺fieldの主光線・光線のaiming収束計算が失敗している）、R80・R81でも同じ値が再現され、issues_backlog.mdに「P011の周辺fieldでfull aiming収束失敗を解消する」として登録済み・未修正のままである。

画面上で光線が途中で切れて見える現象が、この既知のaiming_failed問題の視覚的な現れなのか、それとも別の理由（絞りでの遮光=blocked、または描画側の未知の問題）によるものなのかを確認する。

## 作業

1. 実UIのPreviewタブでP011を選択し、人間が見た画面と同じ条件（既定field・既定sampling）を再現する。
2. 実際にどの光線が画面上で途中終端しているように見えるかをスクリーンショットで特定する。
3. 同条件でtrace APIを直接呼び出し、各光線のstatus（`alive`/`blocked`/`aiming_failed`等）と、実際に返っているpath座標（何点まで経路データがあるか、最終点がどこか）を確認する。
4. 途中終端して見える光線のstatusが、`aiming_failed`（P011の既知backlog項目と一致）なのか、`blocked`（R60で確立した遮蔽光線の描画規則：gray短破線＋終端×マーカー）なのか、それとも別の状態なのかを特定する。
5. `blocked`の場合はR60の意匠（gray破線＋×マーカー）で正しく描画されているか、`aiming_failed`の場合は現在どのような描画がされているか（R73作業4で追加したCarbon warning表示との関係も含む）を確認する。
6. 今回確認した現象が、既存のissues_backlog.mdの「P011の周辺fieldでfull aiming収束失敗を解消する」と同一原因かどうかを結論付ける。同一でない場合、新規の問題として何が起きているかを報告する。

## 完了条件

- 画面上で途中終端して見える具体的な光線が、実データ（status・path座標）で特定されている。
- その原因が、既存のP011 backlog項目（aiming_failed）と同一か否かが、実測に基づき結論付けられている。
- 同一の場合、視覚表現（現状どう見えているか）が誤解を招く表現になっていないか（例：aiming_failedの部分経路が、あたかも正常な光線が遮蔽されたかのように見える等）を評価する。
- 本タスクは調査のみであり、コード修正・描画修正は行わない。修正が必要と判断した場合は、方針・規模感を報告書に記載するに留める。

## 注意

- 「aiming_failedが原因」という結論は、目視ではなく必ずtrace APIの実データ（status・path）で裏付けること。
- P011のaiming_failed問題自体の根本原因調査・修正は本タスクの対象外（既存backlog項目として別途扱う）。今回は「画面表示として何が起きているか」の特定に留める。
