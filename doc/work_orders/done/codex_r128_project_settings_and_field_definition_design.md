# R128：プロジェクト基本設定タブ＋像高ベースfield定義 設計提案 指示書（Codex向け・キュー追加）

## 背景

人間とのUIレビューで、現行の右パネル「Analysis Conditions」に対して次の問題意識が確認された。

1. 波長セット・ウエイトは「最初に決めてほぼ変えない」プロジェクト基礎設定なのに、毎画面の右パネルに常駐している。ラベルも「Analysis Conditions」でプレビューとの共有状態であることが読み取れない（R36のfield残留混乱の温床）。
2. MTF mode（単色/白色）トグルはプレビューに無関係で、R117のパネル別選択導入後は役割自体が減っている。
3. 評価画角は最終的に「センサー像高の10割・7割・0割から逆算した角度」であるべきで、角度直打ちは本来手段にすぎない。R37（近軸70%）・R123 Fit fields（近軸逆算）で部分的に実現済みだが、field定義方式としての格上げと、将来の実光線像高（歪曲込み逆追跡）対応が未設計。

これを受け、**左ナビに「プロジェクト基本設定」タブを新設し、field定義を像高指定モードへ格上げする設計提案**を作成する（R84/R99/R119と同じ設計提案方式。**実装・仕様書変更は行わない**）。本指示書は連続作業キューの**末尾への追加**（R127の後）。キュー運用ルール適用。

## 提案に含めるべき論点

### 1. 情報アーキテクチャ（基本設定タブ）

- 新タブの構成案：波長セット・ウエイト、センサー寸法、field定義方式、image plane policy既定、その他「稀にしか変えない評価基盤」の候補列挙。
- 右contextパネルとの分担：各画面の右に残すべき高頻度項目（ray sampling密度、fieldの一時override、表示トグル等）の整理。「基本設定で定義、右パネルで一時override」の2層モデルの是非。
- ラベル問題：「Analysis Conditions」の改名案（Evaluation Conditions等）、共有状態・override状態の視覚表現。
- MTF modeトグルの扱い：Analysis移設か、R117パネル別選択への一本化（廃止）か。推奨を明示。
- 左ナビのタブ追加がR101のnavigation shell（5画面構成・E2E）へ与える影響。

### 2. field定義の像高指定モード（エンジン仕様案）

- field typeの拡張案：`angle`（現行）／`image_height_paraxial`（近軸逆算、R37/R123の既存ロジックを定義として昇格）／`image_height_real`（歪曲込み実光線逆追跡、将来）。engine_specのどの節にどう追記すべきかの案。
- `image_height_real`に必要なエンジン機構（反復field solve）の規模・R116のaiming知見との関係。段階導入案（近軸を先に定義として固定、実光線は別フェーズ）。
- 像高指定の基準：センサー半対角か、Y/Z個別か（R123のY/Z個別対応・R36のwidth=Y/height=Z仕様との整合）。
- ズーム系での挙動：positionごとにEFLが変わると同一像高でも角度が変わる。position切替時の再解決タイミングの設計（R121 Position Manager・R5 multi-configurationとの整合）。

### 3. 永続化・互換

- 基本設定の保存先：system定義か、AnalysisConditionか、Projectか（ui_spec 10.1の状態単位との対応）。R122のexport/import・snapshotへの反映。
- 既存プリセット（P001〜P013、R37の3点field付き）の移行方法：角度直打ちfieldをどう扱うか（そのまま`angle`型として有効／像高型への変換提案）。
- 後方互換：既存snapshot・exportファイルの読込。

### 4. 各案の規模

- UI側のみで可能な範囲（タブ新設・改名・移設）と、エンジン仕様拡張が必要な範囲（field type）を明確に分離し、それぞれ実装規模（小/中/大）と依存関係を付ける。
- 推奨の段階導入順を1つ提示する。

## 完了条件

- 実測に基づく現状確認（現行の右パネル項目の全列挙と「どの画面のどの結果に効くか」の対応表）を含む。
- **製品コード・テスト・仕様書の変更は一切行わない**。
