# 右パネル レイアウト構造改善 指示書（Codex向け）

## 優先度・着手タイミング

**このタスクを、光線数挙動検証（`codex_q4_ray_count_behavior_check.md`）より先に着手する。** 理由：ray_count_behavior_checkは右パネルのDebugタブに新しいパネルを追加する内容を含んでおり、右パネルの構造問題を先に直さないまま実行すると、縦の伸びすぎ問題を悪化させる。

Layout View描画品質改善・STOP/IMG記号スケール確認と同時期の着手でよいが、右パネルのDOM構造を大きく変更するため、可能であれば別コミットとして分離する。

## 背景

Phase 3を通じて、右パネルにSystem情報・Groups編集・Group Motion（ズーム/フォーカススライダー）・Aperture操作・Decenter/Tilt操作・Build Info（Debug）と、多数のセクションが積み上げ式に追加されてきた。その結果、以下の使い勝手の問題が生じている：

1. 右パネルが縦に長く伸びすぎている。
2. 右パネルをスクロールして下部を見ようとすると、中央パネル（Layout View・チャート）が画面外に流れて見えなくなる。
3. 右パネルの数値をクリックで連続操作しようとすると、レイアウトが動いて操作対象を押しそこなう（レイアウトシフト）。

## 作業

### 1. レイアウトシフトの原因調査（推測で直さない）

1. 実際にクリック連打操作を再現し、操作の前後でDOM/要素の位置（bounding rect）がどう変化するかを記録する。可能であればPlaywrightで、クリック前後のスクリーンショット比較またはbounding box座標のログを取得する。
2. 何が高さの変化を引き起こしているか特定する（候補：ドラッグ中previewの結果表示が出たり消えたりする、validation警告の表示/非表示、dirtyバッジの表示/非表示、evaluated_fields表示の有無、非同期結果到着によるパネルの再レンダリング等）。
3. 原因を特定した上で、該当箇所を修正する（例：結果表示領域を常に一定の高さで確保し、内容が無い時も空白として予約する、警告表示をtooltip/インライン化してレイアウトに影響しない形にする等）。

### 2. 独立スクロール領域の実装

1. アプリ全体のレイアウトをビューポート高さ基準に変更し、中央パネル（Layout View・チャート）と右パネル（コントロール群）がそれぞれ独立した`overflow-y: auto`領域を持つようにする。
2. 右パネルをスクロールしても中央パネルの表示位置は変わらないことを確認する。
3. 左パネル（プリセット一覧等、存在する場合）についても同様に独立スクロールとする。

### 3. 右パネルのセクション構成見直し

1. 現在積み上げ式に並んでいるセクション（System情報、Groups、Group Motion、Aperture、Decenter/Tilt、Build Info/Debug）を、Carbon Accordion（開閉可能な折りたたみ）または既存のタブ構造との組み合わせで整理し、常時全展開ではなく必要な部分だけ開く形にする。
   - 頻繁に操作するもの（Group Motion、Aperture、Decenter/Tiltのスライダー類）は既定で開いた状態、参照頻度の低いもの（Build Info/Debug）は既定で折りたたむ、といった優先度付けを行う。判断はCodexに委ねるが、根拠を報告する。
2. 今後追加される予定のデバッグ情報（光線数挙動検証タスクで追加予定の`ray_sampling`表示パネル等）が、この新しい構造（折りたたみ可能なDebugセクション）に自然に追加できる設計にしておく。

## 完了条件

- クリック連打時のレイアウトシフトが解消されている（原因と修正内容を報告する）。
- 右パネルスクロール時に中央パネルの表示位置が変わらない。
- 右パネルのセクションが折りたたみ可能になり、常時全展開時と比べて縦の長さが大幅に短縮される。
- 既存のE2E（Group Motion、Aperture、Decenter/Tilt操作等）が、新しいレイアウト構造でも壊れずに動作する（セレクタ変更が必要な場合は更新する）。
- 完了報告前にプロセスを再起動し、`build_info.git_commit`がHEADと一致することを確認する。

## 仕様への反映

本タスクで確定するレイアウト構造（独立スクロール領域、Accordion採用、既定の開閉状態）は、`doc/ui_spec.md` 8章（画面構成）に反映する（該当箇所に【レイアウト改訂】と明記し、改訂履歴に1行追加する）。
