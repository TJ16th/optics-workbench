# R83：最適化(O8-13)を見据えたfull aiming持続スループット計測 指示書（Codex向け）

## 背景

R82でaffine aiming cacheの決定論破壊バグを修正した。修正後はcache hit（同一request signatureの再利用）が大幅高速化した一方、修正後の設計は「完全なrequest signatureごとにexact solve済みoriginを保存」する方式のため、**最適化のヤコビアン計算のように毎回わずかに異なる摂動済みconfigurationを評価する場合は、原理的に全てcache missとなり、R82の高速化の恩恵を受けない**（cold pathの速度がそのまま実質的な上限になる）。

人間から「今のスピードは実用的か、特に光学系最適化時が心配」「GPU化は有効か」との質問があり、GPU投資は時期尚早（現行CPU実装で14面1万本off aimingが約98ms＝約10万本/秒、Numba未使用の温存策あり）と回答した。人間はこれを踏まえ、O8-13着手前の判断材料として、最適化を想定したfull aimingの持続スループット（1秒あたり何回evaluateできるか）を実測するよう求めている。

`doc/engine_spec.md`には既に具体的な目標値がある。

- 27.3節「定量的な性能目標」：**最適化粗評価（1候補あたり簡易merit）100〜500ms以内**、**バッチ最適化（100候補の粗評価）10〜60秒以内**。想定環境は「一般的なノートPCまたはミドルクラスデスクトップPCのCPU実行」、GPU高速化は将来拡張と明記されている。
- 25.7節「ヤコビアンバッチモード」：外部有限差分だと変数n個で1反復あたりn+1回のevaluate呼び出しが必要になるところ、エンジン内で基準点の解を全摂動点のwarm startに使い、n+1回分をほぼ1回強のコストにする設計が**規定されている**。ただし現在コードとして実装済みかは未確認。

## 作業

### 1. ヤコビアンバッチモードの実装状況確認

1. `/v1/optics/evaluate`が25.7節の`jacobian`パラメータを受け付け、基準点＋n摂動点をwarm start共有で処理する実装が現在存在するかを、コード・API直接呼び出しで確認する。
2. 存在しない場合、現状の最適化的ワークフローは「n+1回の独立したevaluate呼び出し」（毎回異なるconfiguration、R82修正後は全てcache miss＝cold path）になることを前提として以降の計測を行う。
3. `/v1/optics/evaluate-batch`（R80で確認済み：複数candidate変数評価用）が、内部的にwarm start・CompiledSystemを候補間で共有しているか、それとも単純に候補ごとに独立処理しているかも確認する。

### 2. 持続スループット計測

1. 「簡易merit」相当のサンプリング条件を、R73作業5で実装済みの`ray_fan_error`・`longitudinal_aberration`merit operand実装が実際に使用しているray/field/wavelength数を基準に決定する（独自の想定条件を使う場合は根拠を明記する）。
2. 面数の異なるプリセット（R80と同じP002/P007/P012、可能ならP011も参考値として）で、上記条件のevaluateを「毎回わずかに異なるconfiguration」（例：曲率やshiftを微小変化させた摂動値）で連続実行し、R82修正後のcache missパスの持続スループット（1秒あたりevaluate回数、または1回あたりms）を計測する。
3. 比較のため、同一configurationを連続実行した場合（cache hitパス）のスループットも併記する。
4. HTTP往復・シリアライズのオーバーヘッド（P0タスク6で確認済みの`http_serialization_overhead_ms`と同種の指標）が、この呼び出し頻度で無視できない要素になっているかを確認する。

### 3. 最適化ワークフローへの外挿

1. 想定変数数n（例：5、10、20）と想定反復回数（例：10、30）を置き、現状の「n+1回の独立cold evaluate」モデルで1回のヤコビアン計算・1回の最適化実行全体の所要時間を試算する。
2. 27.3節の目標（1候補100〜500ms、100候補バッチ10〜60秒）と実測値を比較し、現状達成できているか、どの条件で未達になるかを明確にする。
3. ヤコビアンバッチモード（25.7節）が実装された場合の理論的な短縮効果（n+1回→ほぼ1回強）も、現状の実測値をベースに試算し、実装の投資対効果を定量的に示す。

## 完了条件

- ヤコビアンバッチモード（25.7節）の実装有無が確認され、報告書に明記されている。
- cache miss（毎回異なるconfiguration）とcache hit（同一configuration）双方の持続スループットが、複数面数条件で実測されている。
- HTTP/シリアライズオーバーヘッドが呼び出し頻度に対して無視できるかどうかが確認されている。
- 想定変数数・反復回数を置いた最適化ワークフロー全体の所要時間試算が示され、27.3節の目標値と比較した達成状況が明確化されている。
- ヤコビアンバッチモード実装時の理論的な短縮効果が定量的に試算されている。
- 本タスクは調査・計測のみであり、コード修正は行わない。

## 注意

- 「簡易merit」のサンプリング条件は、実装済みのmerit operand（R73作業5）を根拠にすること。仕様書の言葉だけから独自に条件を決め打ちしない。
- cache missを意図的に発生させる摂動値は、物理的に無効な形状（edge thickness負等）にならない範囲で選ぶこと。
- GPU化・Numba化等の実装判断は本タスクの対象外（数値だけ示し、判断は次の意思決定に委ねる）。
