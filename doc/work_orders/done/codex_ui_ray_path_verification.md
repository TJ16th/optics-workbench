# Layout View：光線経路の屈折描画確認 指示書（Codex向け）

## 背景

曲率描画修正後のLayout Viewで、P002（両凸単レンズ）の光線経路を目視したところ、STOP→レンズ→焦点へ滑らかに収束する形に見える。ただし、これが**各面（S1, S2）で実際に屈折計算された折れ線**なのか、単に始点と終点を結んだ見た目だけの曲線なのか、目視では判別できない。過去に面の曲率描画が実際には直線だった前例があるため、同様のパターンでないか確認する。

## 作業

1. Layout Viewで光線経路を描画している箇所のコードを確認する。使っているデータが以下のどちらか確認する：
   - (a) エンジンのtrace応答に含まれる、各面交点を含む光線経路データ（複数点のポリライン。仕様17.1節「光線経路を保存」に対応するもの）。
   - (b) 単に光線の始点・終点（またはfield角度からの概算）だけを使い、UI側で滑らかな曲線を補間・描画しているもの。
2. (a)であれば、実際にP002のtrace応答をログ出力し、1本の光線について、S1のX座標・S2のX座標それぞれに対応する経路点が存在し、そこで方向ベクトル（傾き）が変化していることを数値で確認する。
3. (b)であった場合、これは物理的に正しい屈折を表示していない。エンジンのtrace応答から実際の経路データ（面ごとの交点座標）を取得し、それに基づいてポリラインを描画するよう修正する。
4. 修正後（または(a)で問題なしと確認できた場合）、以下を目視・データ両面で確認する：
   - S1手前の区間で、光線が光軸と平行（無限遠物点の場合）であること。
   - S1通過直後に傾きが変化すること。
   - S2通過直後にさらに傾きが変化すること。
   - S2通過後、焦点に向けて収束すること。
5. 確認結果（該当コード箇所、データ構造、S1/S2での傾き変化の数値）を報告する。

## 完了条件

- 光線経路が実際の面交点データに基づくポリラインであることが、コードとデータの両方で確認されている（目視のみで済ませない）。
- (b)だった場合は修正が完了し、S1/S2での傾き変化が数値で示されている。
