# R97：像面湾曲チャートのギザギザ・階段状異常 調査 指示書（Codex向け）

## 背景

人間からAnalysisタブのスクリーンショット提供と共に、「像面湾曲のグラフが変」との指摘があった。画面には2種類の像面湾曲パネルが写っている。

1. 標準3パネル収差図（Q6導入）内の「像面湾曲 (Field Curvature)」パネル：X軸「焦点ずれ mm」、M(青)/S(赤)の2系列が、なめらかな曲線ではなく**複数箇所で垂直方向にジャンプするノコギリ状（sawtooth）**の形状になっている。
2. 個別チャート版の「像面湾曲 (Field Curvature)」：X軸「field deg」、Y軸「mm」、M(青)/S(赤)の2系列が、**水平区間と垂直方向の落差を繰り返す階段状（staircase）**の形状になっている。

field角の範囲が0〜14.65度程度であることから、対象プリセットはP002（recommended edge-y 14deg）である可能性が高いが、断定はしないこと。

R75で像面湾曲にCoddington方程式による解析的計算を実装済み（従来のRMS探索方式から置き換え）、R76でfield方向のサンプリング密度を16点へ高密度化済みである。この2つのチャートは、軸の向きが違うだけで同じ内在的な非単調・不連続なM/S値を表現している可能性がある（片方が縦方向のジグザグ、もう片方が横方向の階段として見えている、という仮説）。断定せず、実データで確認すること。

## 作業

1. 対象プリセット（P002等、field角0〜14.65度程度の系）で、Field Curvature analysis APIを直接呼び出し、field角ごとのM/S値を数値として取得する。
2. 取得した数値が、画面のグラフと同様に非単調・不連続（階段状・ジグザグ状）になっているか、それとも滑らかであり描画側の問題（点の順序間違い、軸のスケーリング誤り等）なのかを判定する。
3. 数値自体が階段状の場合、R75で実装したCoddington計算のどの部分がこれを引き起こしているかを特定する（例：ある種の丸め、離散的な分岐選択、探索の名残等）。R74/R75の完了報告・実装内容を参照し、想定外の挙動でないかを確認する。
4. 数値が滑らかな場合、UIの描画コード（標準3パネル版・個別チャート版の両方）のどこで階段状・ジグザグ状に見える原因（点のソート順、重複点、補間方式等）が発生しているかを特定する。
5. 標準3パネル版と個別チャート版の両方で同じ現象が再現するかを確認し、共通原因か別々の原因かを明らかにする。

## 完了条件

- 対象プリセットと再現条件が明記されている。
- 異常の原因が、①エンジン側の計算値自体の問題②UI描画側の問題、のいずれであるかが実データで判定されている。
- 原因箇所（具体的な関数・コード）が特定されている。
- 本タスクは調査のみであり、コード修正は行わない。修正が必要な場合は、修正方針・規模感を報告書に記載するに留める。

## 注意

- 「エンジン側が原因」「描画側が原因」という結論は、目視ではなく必ず実データ（API直接呼び出しの数値、DOM実測等）で裏付けること。
- R75・R76の実装内容を鵜呑みにせず、現行コードを実際に確認すること。
