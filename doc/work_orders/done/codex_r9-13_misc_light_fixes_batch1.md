# 軽量確認・改善まとめ（画角/物像間距離、縦収差用語、光線描画範囲、補助表示、防振リミット） 指示書（Codex向け）

複数の軽量な確認・改善をまとめた指示書。それぞれ独立しているので、番号順に進めてよい。

## 1. 有限距離物体・画角決定の仕様確認

### 背景

人間から「有限距離の物体からの光線は出ているか」「物像間距離は光学系で決まるのか、指定のD0か」「画角はセンサーサイズと光学系で決まるのか、指定の画角か」という質問があった。

### 作業

1. エンジン仕様15.2節（有限距離物体）を確認し、`object_points`（position_mmで物点位置を指定する方式）が現在Workbench UIから設定可能か確認する。
2. 現在のプリセット（P001〜P007）がすべて無限遠物体（`type: angular`）を前提にしているか確認する。
3. 画角（field）の決定方法を確認する：現在は`theta_y_deg`/`theta_z_deg`を直接指定する方式（仕様14.1節）であり、「センサーサイズから自動計算される画角」ではなく「ユーザーが指定したfield角」であることを確認する。
4. 上記を踏まえ、以下を報告する：
   - 有限距離物体からの光線追跡は現在UIから試せるか（試せない場合、Issueバックログへ「有限距離物体UI対応」として追記する）。
   - 画角とセンサーサイズ・EFLの関係（`h = f・tan(θ)`、仕様21.3節）をUI上で分かりやすく提示できているか（例えば、指定fieldでの理論像高がセンサー範囲内に収まっているかの視覚的フィードバック等）。不足があればIssueバックログへ追記する。

## 2. 「縦収差」の用語・定義の仕様正誤

### 背景

エンジン仕様21.1節では`longitudinal aberration`（縦収差）と`chromatic aberration`（色収差）が並列項目として書かれているが、Q6で実装した「Longitudinal Aberration」パネルは複数波長を重ねて描画しており、実質的に球面収差＋軸上色収差を1つのグラフで示している。これは業界慣習（縦収差図に複数波長を重ねるのが一般的）としては妥当だが、**仕様の文言がこの実態を反映していない**。

### 作業

1. `doc/engine_spec.md` 21.1節の該当行を修正する：
   - 修正前：`| longitudinal aberration | 縦収差 |`
   - 修正後：`| longitudinal aberration | 縦収差（単色では球面収差、複数波長重ね描きでは軸上色収差を含む） |`
2. 21.1節に一言、単色版と複数波長版の違いを明記する小節を追加する（過剰な記述は不要、2-3行でよい）。
3. glossaryの`longitudinal_aberration`エントリがあれば、同様に説明を補足する。

## 3. レイアウト図の光線描画範囲

### 背景

人間から「レイアウト図で、絞りより左側（物体側）の光線がどこまで描かれているか分からない」「センサーが無かった場合の表示ができるとよい」という指摘があった。

### 作業

1. 現在、光線経路の描画が絞り（STOP）位置から始まっているか、それより物体側にも一定区間描画されているか確認する。
2. 物体側の描画範囲について、以下のいずれかを実装する（判断して報告する）：
   - (a) 固定の一定距離（例：レンズ全長の20%程度）を物体側に延長して描く。
   - (b) 描画範囲をトグルで切り替えられるようにする（オン/オフまたは複数段階）。
3. 「センサーが無かった場合の光線がどう続くか」の表示について、簡易なトグル（センサー面での遮断を無視して、光線を焦点位置または一定距離まで延長して描く）を追加する。過剰実装は避け、シンプルなオン/オフで良い。
4. 各種条件（プリセット切り替え、群移動等）を変えた際に、描画スケール（ズームレベル）が不用意に変わらないようにする。現状の挙動を確認し、問題があれば固定スケールオプションを追加する。

## 4. レイアウト図補助表示（焦点・主点位置）

### 背景

近軸計算で得られる焦点位置・主点位置を、レイアウト図上にマーカー表示できるようにしたいという要望。

### 作業

1. 近軸解析APIから焦点位置・前側/後側主点位置を取得し、レイアウト図上にマーカー（縦線または小さな記号）として重ねて表示する機能を追加する。
2. 表示のオン/オフを切り替えられるようにする（既定はオフ、または軽量なので既定オンでもよい。判断して報告する）。

## 5. 防振群シフト量のリミット

### 背景

人間から「防振（OIS）群のシフト量に上限を決めておかないと、有効径が決まらない」という指摘があった。これは正しい指摘で、実際の光学設計では、防振群の最大シフト量を決めてから、その状態でもケラレが生じないように前後の面の有効径を設計する。

### 作業

1. 現在のdecenter編集UI（P3-4）で、シフト量に上限の概念があるか確認する。無ければ、群定義またはUI設定として「最大シフト量」を持てるようにする（必須ではなく任意項目としてよい）。
2. 最大シフト量が設定されている場合、その量だけシフトした状態でケラレが発生していないか（有効径が足りているか）を、簡易な警告として表示できるようにする。
3. 本格的な「シフト量から逆算した有効径の自動設計」は大きな機能のため、今回は「最大シフト量の設定」と「その状態での簡易ケラレ警告」までに留める。より高度な機能はIssueバックログへ追記する。
