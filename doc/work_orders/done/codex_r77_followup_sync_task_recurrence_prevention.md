# R77フォローアップ：同期タスク再発防止設定 指示書（Codex向け）

## 背景

`2026-07-13_report_sync_outage_investigation.md`で、クロスワークスペース同期タスク`OpticsCrossWorkspaceDocSync-R55`（R55で導入）が外部要因で停止し、約10時間`Ready`のまま自動復帰しなかったことが判明した。原因調査で以下2点が再発防止候補として提示され、人間が承認した。

1. Task Schedulerの失敗時再起動設定（`RestartCount`、`RestartInterval`）を設定する。
2. Task Scheduler Operational履歴を有効化し、次回停止時に停止主体を追跡可能にする。

## 作業

1. `OpticsCrossWorkspaceDocSync-R55`タスクへ、失敗時の自動再起動設定を追加する。具体的な値（例：`RestartCount=3`、`RestartInterval=PT1M`程度）は、無限ポーリングループであるスクリプトの性質と、頻繁な再起動が同期処理自体に悪影響を与えないことを考慮して妥当な値を選定し、根拠を報告書に明記する。
2. Task SchedulerのOperational履歴（`Microsoft-Windows-TaskScheduler/Operational`ログ）を有効化する。
3. 設定変更後、タスクを再起動し、通常通り同期が機能することを確認する（R55/R56導入時と同様の検証：正本への一時的な変更→Claude側参照コピーへの反映確認→元に戻す）。
4. 設定変更が同期タスクの多重起動や既存の750msポーリング・SHA-256補完等の既存動作に悪影響を与えていないことを確認する。
5. 可能であれば、意図的にタスクプロセスを終了させて自動再起動が実際に機能することを検証する（安全に実施できる場合のみ）。困難な場合は、設定値が正しく適用されていることの確認（`schtasks /query`等の実際の設定値表示）に留めてよい。

## 完了条件

- `RestartCount`・`RestartInterval`が設定され、実際の値が報告書に明記されている。
- Operational履歴が有効化されていることが確認されている。
- 設定変更後も同期処理が正常に機能することが、実際の同期確認（一時的な変更の反映と復元）で示されている。
- 可能であれば自動再起動の実地検証結果が示されている。困難な場合はその理由と、代替の設定値確認方法が明記されている。
- 本タスクは運用スクリプト・Windowsタスク設定のみの変更であり、エンジン・UI・正本仕様のコードは変更しない。該当する場合はpytest/UI CIは対象外としてよい。

## 注意

- 既存の同期の一方向性（Claude側からの書き戻し無効等、R55/R56で確立した規約）を壊さないこと。
- 設定変更中に同期が一時的に止まっても実害はないが、変更後に正常復帰することを必ず確認すること。
