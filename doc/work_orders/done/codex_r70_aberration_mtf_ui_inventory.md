# R70：収差図・MTF表示UI 現状棚卸し 指示書（Codex向け）

## 背景

人間から「SAとかの収差図・MTF表示周りのUI（必要に応じてエンジンも）に着手したい」という要望があった。

`doc/ui_spec.md`を確認したところ、View一覧（17.1〜17.6：Optical Layout / Ray Path / Spot Diagram / MTF Chart / PSF Heatmap）に、**Ray Fan（瞳座標に対する横収差）・Longitudinal Aberration（縦収差＝単色では球面収差、複数波長では軸上色収差、`doc/engine_spec.md` 1372-1373行）・Field Curvature・Distortion専用のView定義が見当たらない**。一方でこれらは以下のように「実行可能」「表示可能」であるかのように各所で言及されている。

- P002「longitudinal aberration graphが表示可能」（9.4節）
- P007/P009/P010「spot、ray fan、paraxial解析を実行できる」（9.4節）
- P004/P011/P012「MTF、distortion、field curvatureが表示可能」（9.4節）
- 22.3節のExport対象一覧に「Field Curvature」が単独項目として存在

この「プリセット説明文には書いてあるが、View仕様には専用セクションがない」という食い違いは、これまでR64（非球面係数のUI非表示）・R65（P004未実装）・R68（`at_exit_pupil`未実装）で繰り返し発見されてきたパターン（**仕様書・プリセット説明文の記述と実装状況が一致しない**）と同種の疑いがある。実装せず、まず実態を確認する。

## 作業：現状棚卸し

以下の5種類のチャート／解析について、代表プリセット（P002：球面単玉、P003：アクロマート、P007またはP011：高速ダブルガウス、P009/P010：非球面）を実際にUIで選択し、**目視ではなく実DOM・実データで**現状を確認する。

1. **Ray Fan（横収差図）**：瞳座標に対する横収差プロットが実際に描画されるか。P007/P009/P010の説明文が主張する「ray fanを実行できる」を実UIで検証する。
2. **Longitudinal Aberration（縦収差図）**：単色での球面収差カーブ、複数波長重ね描きでの軸上色収差カーブが実際に描画されるか。P002の説明文が主張する「longitudinal aberration graphが表示可能」を実UIで検証する。
3. **Field Curvature（像面湾曲図）**：tangential/sagittal像面のfield角に対するカーブが実際に描画されるか。
4. **Distortion（歪曲収差図）**：% distortion対field角のカーブが実際に描画されるか。
5. **MTF Chart**：17.5節の仕様（sagittal/meridional、white/monochromatic、geometric/diffraction included切替、evaluation plane切替）のうち、実際にUIで動作する項目とそうでない項目を切り分ける。

各項目について、次を明確に区別して報告する。

- **実装済み・動作確認**：実際にチャートが描画され、データが妥当であることを確認した（スクリーンショット・DOM値を添付）
- **部分実装**：一部の切替（例：sagittal/meridional）が機能しない、特定プリセットでのみ動作する等
- **未実装**：説明文・仕様書の記述にもかかわらず、UIに存在しない
- **エンジン側は対応済みだがUI未接続**：`/v1/analysis`等のAPIレスポンスにデータは含まれるが、UIが描画していない

また、エンジン側の対応状況も確認する。`ray_fan.py`（`doc/engine_spec.md` 2871行で言及）、`ray_fan_error`・`longitudinal_aberration`オペランド（同2022-2023行）が実際にAPIレスポンスへ含まれるか、`optics_engine`のコードとAPIレスポンスの両方で確認する。

## 完了条件

- 5種類のチャート／解析それぞれについて、上記4区分のいずれかに分類され、根拠（DOM値、APIレスポンス、スクリーンショット）とともに報告書に明記されている。
- `doc/ui_spec.md`のView一覧（17章）に不足しているセクションがあれば、その一覧を提示する（本タスクでは仕様書の修正は行わなくてよいが、不足リストは明記する）。
- 発見した各ギャップについて、修正・実装の規模見積もり（小・中・大）を、R49・R68と同様の形式で提示する。
- 優先順位案（どのギャップから着手すべきか）を1つ提示する。
- **本タスクではUI・エンジンの実装は行わない。** コード変更は対象外（バグではなく仕様追記の必要が明白な最小限のドキュメント修正のみは可）。

## 注意

- 「表示できている」「動作している」という判断は、プリセット説明文の記述を鵜呑みにせず、必ず実際にブラウザ操作・DOM確認・APIレスポンス確認で裏付けること。
- 5種類それぞれ独立して確認し、1つが動いていたからといって他も動いていると推測しないこと。
