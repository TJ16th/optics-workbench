# R57：軸上主光線の片側欠落／Annulus STOPマーカー表示の調査 指示書（Codex向け）

## 背景

R56完了後、人間がP005（カセグレン）のLayout Viewスクリーンショットを確認したところ、以下2点の疑問が見つかった。

1. **軸上主光線の下側の線が欠けているように見える**：画面上、M2からM1上側を経由してIMGへ向かう実線（chief/marginalの representative ray）は描かれているが、これに対称なはずの下側の実線が見当たらない。
2. **Annulus STOPマーカーの図示の意味が読み取りにくい**：R54でSTOPマーカーを「正円→内径/外径それぞれの位置に縦線4本」という断面表現に修正したはずだが、この画面ではSTOP位置に描かれている要素が何を表しているのか、目視だけでは判別しづらい。

いずれも人間の目視による疑問であり、AI（Claude）側もこの時点では原因を断定していない。R28cで「baseline marginal rayがstatus条件でフィルタされ、一部のプリセットで描画から漏れていた」という類似の前例があるため、同種の実装上の見落としである可能性を念頭に、**目視で結論を出さず、必ず実データで確認すること**。

## 作業

### 1. 軸上主光線の描画状況の確認

1. P005で、baseline layer（chief ray・marginal ray）として実際にAPI/エンジンから返されているray一覧を取得し、各rayのfield・status・pathの点列を確認する。
2. 軸上field（field=0、on-axis）について、chief rayが何本返されているか、そのY座標の推移（M2・M1・IMG各面での高さ）を確認する。
3. 光学的には、軸上fieldのchief rayは絞り中心（Y=0）を通るため、理想的には光軸上をそのまま通る1本のみが物理的に正しい可能性がある。一方、画面に描かれている実線はM1上側で非ゼロの高さを経由しているように見える。**これがchief rayなのかmarginal rayなのか、実際のデータのray種別（chief/marginal/density等のラベルやtag）を確認して特定する。**
4. marginal rayであった場合、対称のはずの下側（-Y側）のray が実際にデータとして存在するか、存在するのに描画されていないだけなのか（R28cと同種のstatus起因のフィルタ漏れ等）を確認する。
5. 原因を特定し、実装上のバグであれば修正する。「軸上主光線は光軸に沿った1本が正しい仕様である」等、バグではなく仕様通りと判明した場合は、その根拠（面定義・fieldの角度・絞り中心通過の条件等）を明確に報告する。

### 2. Annulus STOPマーカー表示の再確認

1. P005の実DOM/SVGで、Annulus STOPマーカーとして現在何個の要素が、どの座標に描画されているかを計測する（R54の完了報告と同じ計測粒度：内径±・外径±それぞれの位置、線の本数）。
2. R54完了報告時点の実測値（内径36.8px、外径92px、境界線4本）と一致しているか確認する。
3. 一致していない場合、R54以降の変更（R55/R56等のドキュメント同期タスクはコード変更を伴わないはずだが、念のため）で意図せず退行していないか確認する。
4. 一致している場合でも、「4本の短い縦線」という表現が、実際のスクリーンショットの縮尺・色では視認しづらい可能性がある。視認性向上（線を長くする、色のコントラストを上げる、ホバー時にラベルを出す等）が必要かどうかを検討し、対応案を報告する（この場での実装要否は完了条件に含めない。次の指示で判断する）。

## 完了条件

- 軸上主光線の描画について、実データ（ray一覧のfield・status・座標）に基づいた原因（バグ／仕様通り）が特定され、バグであれば修正されている。
- Annulus STOPマーカーの現在の実測値がR54時点と比較して報告されており、退行の有無が明確になっている。
- 視認性についての改善案（実装は任意）が報告に記載されている。
- 修正を行った場合、修正後のLayout Viewスクリーンショットが`doc/reports/screenshots/`に保存され、報告書から参照される。
- 既存テストがグリーン。
- コード変更を伴う場合、完了報告前にプロセスを再起動し、`build_info.git_commit`がHEADと一致することを確認し、断定形で報告に記載する（未来形で締めない）。
- **完了報告の「実装根拠」には、コミットメッセージだけでなく実際のコミットハッシュ値を必ず併記する**（R54・R56で同種の記載漏れが続いているため、改めて徹底する）。

## 注意

- 目視の印象だけで「間違っている／正しい」と断定せず、必ずデータ・DOM実測に基づいて報告すること。
- 軸上主光線が仕様上1本であるべきか、上下対称の2本であるべきかは、報告の中で仕様的根拠（engine_spec.mdの該当節等）とともに明確にすること。曖昧なまま「見た目を対称にする」修正はしないこと。
