# R98：フォーカス群設定済みの実用50mm F1.4プリセット追加 指示書（Codex向け）

## 背景

既存のP011（Planar型6枚ダブルガウス50mm F1.4）は、周辺fieldでfull aiming収束が失敗する既知の未修正問題（alive213/aiming_failed12）を抱えている。また、既存プリセットにはフォーカス群・フォーカスポジションが実用的に設定されたものが無い（P003のFOCUS_Gは、R2の既知の制限によりOIS_Gと同一ブロックを参照する教育用MVP簡略化のままである）。

人間から、次の2点を満たす新規プリセットの追加要望があった。

1. フォーカス群・フォーカスポジションが設定されている（P003のFOCUS_G/OIS_G同一ブロック問題を引きずらない、独立した専用フォーカス群であることが望ましい）。
2. 実用的に性能が出て光線がちゃんと通る（P011のようなaiming_failedが出ない）、50mm F1.4のプリセット。

参考画像として、ミノルタロッコール・キヤノン・ペンタックス・ズイコーの4社の50mm F1.4レンズの構成図（いずれも7枚程度のダブルガウス派生型、中央STOPを挟む構成）が提示された。これらの正確な処方データ（曲率・硝材等）は画像から読み取れないため、**これらの具体的な複製ではなく、同種のトポロジー（7枚程度のダブルガウス派生型）を参考にした、物理的に妥当な独自設計**とすること。

## 作業

### 1. 光学設計

1. EFL≒50mm、F値≒1.4を目標に、7枚程度のダブルガウス派生型（P011の対称6枚Planar型より1枚多い、非対称または補正用要素を追加した構成）を設計する。既存プリセット追加の慣例（P004/P011/P012等）に従い、物理的に妥当な曲率・硝材（N-BK7/N-F2等の既存カタログ材質）を用いる。
2. **最重要要件**：推奨field・既定samplingで、P011のようなaiming_failedが実質的に発生しない（目安：alive比率が既存の良好なプリセット、例えばP012同様ほぼ100%）ことを設計段階で確認する。ナイーブな設計でaiming_failedが出る場合、曲率・間隔を調整して再設計すること（P011と同じ問題を抱えたまま出荷しない）。
3. 全エッジ厚が正であることを確認する（Layout View破綻防止、既存の設計規約）。

### 2. フォーカス群の設定

1. 設計した光学系の一部を「FOCUS_G」として、独立した専用フォーカス群に設定する（P003のようにOIS_Gと同一ブロックを共有しない）。
2. 無限遠位置と、50mm F1.4として現実的な近距離撮影位置（目安：0.45〜0.6m程度）の2つ以上のfocus positionを定義する。
3. 各focus positionで、近軸像位置が実際に変化し、意図通りフォーカス群の移動で合焦することを近軸計算・実光線追跡の両方で確認する。
4. 各focus positionで、推奨field・既定samplingでのray throughput（alive比率）が良好であることを確認する（無限遠側だけでなく近距離側でも同様に確認する）。

### 3. プリセット登録・仕様更新

1. 新規プリセットP013として登録する（日英名称を付与、ダブルガウス派生型・50mm F1.4・フォーカス群付きであることが分かる名称にする）。
2. `doc/ui_spec.md` 9.4節の処方一覧・9.1節のプリセット数、`doc/engine_spec.md`（該当箇所があれば）を更新する。
3. 既存プリセットの定義・数値には影響を与えないことを確認する。

## 完了条件

- 新規プリセットP013が、EFL≒50mm・F値≒1.4を達成していることが近軸計算で確認されている。
- 全エッジ厚が正であることが確認されている。
- 推奨field・既定samplingで、無限遠・近距離フォーカス双方において、P011のようなaiming_failedが実質的に発生しない（高いalive比率である）ことが実測で示されている。
- フォーカス群移動により近軸像位置が実際に変化し、合焦の挙動が近軸・実光線追跡の両方で確認されている。
- `doc/ui_spec.md`（該当あれば`doc/engine_spec.md`）が更新されている。
- 既存プリセット（P001〜P012）の定義・数値に影響がないことを確認している。
- 既存テストが全てグリーンで、新規プリセットを固定する回帰テストが追加されている。
- レイアウト図・収差図等のスクリーンショットで、新規プリセットが正常に描画・解析できることを示している。
- 完了報告前にプロセスを再起動し、`build_info.git_commit`がHEADと一致することを断定形で記載する（未来形で締めない）。
- **完了報告の実装根拠には、コミットメッセージだけでなく実際のコミットハッシュ値を必ず併記する。**

## 注意

- 参考画像の4レンズの正確な処方を複製することは求めていない（画像から読み取れる情報が不十分なため）。同種のトポロジーを参考にした独自の物理的に妥当な設計とすること。
- 「aiming_failedが発生しない」という主張は、目視ではなく必ず実測（alive/aiming_failed/blocked件数）で裏付けること。P011と同じ設計上の問題を引き継がないこと。
- P003のFOCUS_G/OIS_G同一ブロック問題（R2既知）を、新規プリセットで繰り返さないこと。
