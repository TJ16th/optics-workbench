# R21報告の矛盾確認：Q1-R8リネーム・移動の実行者特定

## 背景

R21（`codex_r21_rename_files_with_task_numbers.md`）の完了報告の対応表で、Q1〜R8の「旧名」「新名」が完全に一致している（例：`codex_q1_layout_view_rendering_quality.md` → 同名）。これは「リネームが不要だった＝実行時点で既に番号付き名称だった」ことを意味する。

しかし、直前のR8（`codex_r8_work_orders_active_done_check.md`）の完了報告では、同じファイルが**番号無しの名称**（`codex_layout_symbol_scale_check.md`等）として`done/`へ移動されたと記録されている。R8のコミット/報告タイムスタンプは08:35、R21含む一連のファイルの更新日時は08:41だった（人間によるフォルダ確認で判明）。

つまり、08:35から08:41の間に、Q1〜R8のファイル群がリネーム＋（必要なら）移動されているはずだが、**R8の報告にもR21の報告にも、この操作を自分が行ったという記述がない**。何らかの操作が、どのタスクにも帰属しないまま実行されたように見える。

## 作業

1. `git log --oneline --all -- doc/work_orders/ doc/reports/`で、08:35〜08:41相当の時間帯にコミットされた変更を確認する。
2. 該当コミットの内容（`git show <hash> --stat`）を確認し、Q1〜R8のリネーム・移動がどのコミットで、どのタスク文脈で行われたかを特定する。
3. 特定できた場合：そのコミットが実行された経緯（R8の実行中に追加で行われた、R21の準備作業として行われた等）を報告する。もし特定のタスク番号に紐づかない「名前のない」コミットであれば、その旨も正直に報告する。
4. 特定できない場合（コミット履歴からも判別不能な場合）：現状のファイル配置自体は正しい状態であることは人間が確認済みなので、実害はないと結論づけつつ、原因不明である旨を正直に報告する。
5. 今後、同種の「どのタスクにも紐づかない変更」が起きないよう、AGENTS.mdの作業規律に一言指針を追加できないか検討する（例：「明示的に指示されたタスクの範囲外で、副次的にファイル操作を行う場合も、その操作を完了報告のNotesセクションに明記する」等）。過剰なルール追加は避け、必要と判断すれば追記、不要と判断すればその理由を報告する。

## 付随作業：`codex_p0-7_performance_work_order.md`への番号付与

R21はこのファイルへの番号付与を「指示書に具体的な置換名が無かったため」保留した。人間側の台帳ではこのタスクは`P0-7`として管理されている。このファイルを`codex_p0-7_performance_work_order.md`へ`git mv`でリネームする（内容変更は行わない）。
