# Layout View：凡例の追加 指示書（Codex向け）

## 背景

Layout Viewには、これまでの改修で複数の視覚的な意味付けが積み重なっている：

- R27：baseline layer（chief ray＝太い実線、marginal ray＝破線、上下2本）
- R1：波長色分け（F線系＝青系、d/e線系＝緑黄系、C線系＝赤系）
- Q1〜Q6：density layer（sampling由来の光線、薄い線）、ガラス塗り分け（空気＝透明、ガラス＝薄い色）、有効径境界線

これらは実装時にそれぞれ規約化されているが、**画面上に凡例が無く、線の太さ・実線/破線・色の意味がユーザーに伝わらない**。R28c調査でmarginal光線の表示有無を目視確認する際も、実装を知っている前提でなければ判別が困難だった。

## 作業

1. Layout Viewパネル内（または直下）に、凡例を表示する領域を追加する。
2. 凡例に含める項目：
   - 光線の線種：chief ray（太い実線）、marginal ray（破線）、density ray（薄い線、sampling由来）
   - 波長の色分け：F線（青系）、d/e線（緑黄系）、C線（赤系）
   - 面・要素の色分け：ガラス領域（塗りつぶし色）、空気区間（透明）、接合面（控えめな線種）
   - 近軸マーカー（R12で追加済み）：焦点位置（F'）、主平面（H1/H2）
   - STOP・IMG等の要素記号
3. 凡例は、実際に現在の表示に含まれる要素のみを動的に出す（例：decenter/tiltが無いプリセットでは非対称マーカーの凡例は不要、等）か、全項目を常時表示する固定凡例にするか、判断して報告する（過剰な動的判定は避け、シンプルな固定凡例で十分ならそちらを優先してよい）。
4. i18n対応（ja/en）を行い、`npm run i18n:coverage`をグリーンに保つ。
5. 凡例のオン/オフ切り替えができるとよいが、必須ではない（判断してよい）。

## 完了条件

- Layout Viewに凡例が表示され、線種・色の意味が視覚的に確認できる。
- i18n ja/en対応済み、`npm run i18n:coverage`グリーン。
- 既存のE2Eが壊れていないか確認済み。
- 完了報告前にプロセスを再起動し、`build_info.git_commit`がHEADと一致することを確認し、断定形で報告に記載する（未来形で締めない）。
