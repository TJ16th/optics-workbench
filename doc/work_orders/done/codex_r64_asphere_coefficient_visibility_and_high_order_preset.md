# R64：非球面係数のUI可視性確認／高次非球面（変曲点あり）プリセット新設 指示書（Codex向け）

## 背景

R62でP009（非球面singlet、conic + A4のみ）を追加した際、人間から「P009の非球面パラメータ（conic、A4等）はUIのどこで確認できるのか」という質問があった。

`doc/ui_spec.md` 12.1節のSurface Table標準列を確認したところ、`surface_type`（`aspherical_even`という表示）はあるが、**conic・A4等の非球面係数そのものの値を表示する列が規定されていない**。R47で発生した「annulusのinner/outer半径がSystemタブの面テーブルに表示されない」という過去の不備と同種のパターンの疑いがある。ただしこれは仕様書の記述に基づく推測であり、実際のUIで表示されているかどうかは未確認である。

また、人間から「P009よりもっと非球面量の多いレンズ、スマホレンズのように変曲点（sag曲線の凹凸が反転する点）があるレンズも確認したい」という要望があった。engine_spec.mdの記述（`{surface_id}_A4 / _A6 / _A8 ...`）から、高次の偶数次非球面係数は仕様上サポートされているとみられる。

## 作業

### 1. 非球面係数のUI表示状況を確認する

1. 実際のUI（Systemタブ・Surface Table）で、P009を選択した状態でASP1面のconic・A4の値が何らかの形で確認できるか、実DOM/画面で確認する（推測ではなく実際に操作して確認すること）。
2. 表示されていない場合、Surface Tableに（またはそれに準ずる詳細表示に）conic・非球面係数（A4, A6, A8...で値が設定されているもののみ）を表示する列・欄を追加する。表示されている場合は、その表示方法を報告し、変更不要と判断してよい。
3. `doc/ui_spec.md` 12.1節に、実際の表示仕様を反映する（列が無ければ追加する）。

### 2. 高次非球面（変曲点あり）プリセットの新設

1. 現在の最終プリセット番号をコードで確認し、次の番号で新規プリセットを追加する。
2. P009よりも非球面量が大きく、**sag曲線に実際に変曲点（曲率の符号が半径方向に反転する点）を持つ**非球面singletを設計する。conic・A4に加えA6・A8等の高次項を使い、スマホカメラレンズに見られるような複雑な非球面形状を狙う。
3. 変曲点が実際に存在することを、sag関数の数式・数値計算（例えば複数半径点でのsag値・2階微分やcurvatureの符号変化）で確認し、目視ではなく数値で示す。
4. `doc/ui_spec.md` 9.1節の数値検証規約に従い、近軸トレースと実光線追跡で検証してから数値を凍結する（EFL・F値・ケラレ有無を確認）。
5. 可能であれば、P002またはP009との球面収差比較（spot RMS）も示す。
6. Layout Viewで、変曲点を含むsag形状が視覚的にも（可能な範囲で）確認できるスクリーンショットを取得する。

## 完了条件

- 非球面係数のUI表示状況が実際の操作で確認され、必要な表示追加が行われている（または既存表示で十分なことが確認されている）。ui_spec.md 12.1節が実態と一致している。
- 新規プリセットのsag曲線に変曲点が実際に存在することが、数値計算で示されている。
- 新規プリセットが近軸トレース・実光線追跡で検証され、EFL・F値・ケラレ有無が報告書に数値で明記されている。
- 新規プリセットが`doc/ui_spec.md` 9.1/9.4節に追加され、プリセット数も更新されている。
- スクリーンショットが`doc/reports/screenshots/`に保存され、報告書から参照される。
- 既存テストがグリーン。新規プリセット追加時の回帰（自然順テスト等）も確認する。
- 完了報告前にプロセスを再起動し、`build_info.git_commit`がHEADと一致することを断定形で記載する（未来形で締めない）。
- **完了報告の実装根拠には、コミットメッセージだけでなく実際のコミットハッシュ値を必ず併記する。**

## 注意

- 作業1と作業2は独立した内容なので、通常規約（1タスクずつ・完了報告後に停止）に従って進めてよい。
- 新規プリセットの番号は必ず実コードで現在の最終番号を確認してから採番すること。
- 「変曲点がある」という主張は、目視のsagカーブの見た目ではなく、必ず数値（curvatureの符号変化等）で裏付けること。
