# R69：視覚評価コンポジット（模型眼接続）実装 指示書（Codex向け）

## 背景

R34（`2026-07-11_r34_eye_model_backlog.md`）でIssue登録のみだった「アフォーカル系のアイポイントに眼球モデルを接続し、網膜結像として評価したい」という要望について、R68（`2026-07-13_r68_eye_model_connection_design_review.md`）で設計調査を行った。

R68の結論は以下の通り。

- 単純な面列延長（`eye_reference`の後段に模型眼面＋網膜`sensor`を並べる）は技術的には可能だが、既存afocal指標（射出瞳、アイレリーフ、角度MTF）と模型眼側評価が混線するため製品仕様としては不採用。
- 推奨案（規模：中）は、**`eye_reference`を「終端」ではなく「装置区間と模型眼区間の境界」として扱う視覚評価コンポジット**。単一面列・既存traceを維持しつつ、装置側角度評価（`instrument`）と網膜側位置評価（`retinal`）を結果として分離する。
- 標準模型眼の初期候補は**簡約Gullstrand模型眼（無調節）**。処方は下表（出典：Wiley-VCH Handbook of Optical Systems, Table 36-8, 587nm基準）。

| 面 | 半径 R (mm) | 後方厚み (mm) | 後方屈折率 |
|---|---:|---:|---:|
| 角膜前面 | +7.70 | 0.50 | 1.376 |
| 角膜後面 | +6.80 | 3.10 | 1.336 |
| 水晶体前面 | +10.0 | 3.60 | 1.4085 |
| 水晶体後面 | -6.00 | 17.187 | 1.336 |
| 網膜（初期版は平面近似） | -17.2（曲面は次段階） | 0 | - |

材料は`CORNEA(n=1.376)`、`AQUEOUS_VITREOUS(n=1.336)`、`LENS_EQ(n=1.4085)`の`constant`材料として表現する。装置から角膜まではAIR。初期capabilityは単色587.56nm・固定4mm瞳・無調節・平面網膜に限定する（R68の制限方針を踏襲）。

本タスクはR68が提示した「次段階の実装タスク案」6項目を、以下の作業1〜5として指示する。**作業は依存関係があるため、通常規約（1タスクずつ・完了報告後に停止）で順番に進めること。バッチ実行モードは使わない。**

## 作業1：正本仕様への視覚評価コンポジット追加

1. `doc/engine_spec.md`に、視覚評価コンポジットの概念（`eye_reference`を境界として扱うモード、境界前後の責務分離）を追加する。
2. 終端・境界の規約、結果schema（`instrument`：射出瞳・アイレリーフ・角度spot/PSF/MTF・残存ディオプター／`retinal`：網膜spot/PSF/MTF）、単位（`instrument`は角度・cycles/degree、`retinal`は長さ・lp/mm）を明記する。
3. 初期制限（簡約Gullstrand・単色587.56nm・固定4mm瞳・無調節・平面網膜）を明記する。
4. 主`aperture_stop`は装置のray aiming基準、`eye_reference`は眼瞳クリップ・接続位置として扱う規約を明記する（初期版は模型眼内に第2の`aperture_stop`を作らない）。
5. `position_mode: at_exit_pupil`について、R68で「仕様記述はあるが自動配置処理が実装されていない」と判明した点を修正範囲に含める（実際のコンパイル位置へ反映する）ことを明記する。

## 作業2：エンジン実装

1. `optics_engine/models.py`・`validation.py`・`system.py`・`tracing.py`・`visual.py`を対象に、以下を実装する。
   - `eye_reference`を境界indexとして保持し、境界後に模型眼の`refractive`面と終端`sensor`（網膜相当）を許可する。
   - 境界より後のpowered surfaceを、装置側`instrument`結果（射出瞳・アイレリーフ・角度MTF等）の計算対象から除外する（R68で判明したアイレリーフ誤算出の再発防止）。
   - `position_mode: at_exit_pupil`を実際のコンパイル位置に反映する処理を追加し、`fixed_offset`と合わせて直接テストする。
2. 既存の`focal`/`afocal`の二択・既存プリセットのvalidation・trace挙動に影響がないことを確認する。
3. 単体テスト・回帰テストを追加する。

## 作業3：簡約Gullstrand模型眼プリセットとgolden test

1. 背景に記載した簡約Gullstrand模型眼の処方を、内部プリセット（既存のP001〜P012とは別枠、模型眼単体または既存afocal系＋模型眼接続のデモ系として追加）として実装する。
2. 単色587.56nm・平面網膜・固定瞳という初期制限内で、`instrument`結果と`retinal`結果の両方が実光線追跡で取得できることを確認する。
3. golden test（近軸検算・実光線追跡の期待値固定）を追加する。数値は目視ではなく計算で確定させる。

## 作業4：API・UI対応

1. API・`/v1/meta`のcapabilitiesへ、視覚評価コンポジットの評価モードを追加する。
2. UIに評価モード切替（装置側`instrument`表示／網膜側`retinal`表示）と、対応する結果表示（spot/PSF/MTF等）を追加する。
3. i18n（ja/en）キーを追加する。
4. Layout Viewでのスクリーンショットを取得する。

## 作業5：既存afocal系への回帰確認

1. 既存のafocal系プリセット（P006、P008）の射出瞳、アイレリーフ、角度MTFが、本タスクの変更前後で数値的に不変であることを回帰テストで確認する。
2. 変更前後の実測値を報告書に明記する。

## 完了条件（全作業共通）

- 作業1〜5がこの順で実施され、各作業の完了報告に実装コミットハッシュが明記されている。
- 簡約Gullstrand模型眼の処方が実コードに実装され、`instrument`/`retinal`両結果が実光線追跡の数値で報告書に示されている。
- 既存afocal系（P006、P008）の既存指標が本タスクにより変化していないことが、変更前後の数値比較で示されている。
- `doc/ui_spec.md`・`doc/engine_spec.md`が実コードと一致するよう更新されている。
- UIスクリーンショットが`doc/reports/screenshots/`に保存され、報告書から参照される。
- 既存テストがグリーン。新規追加分の回帰（golden test、自然順テスト等）も確認する。
- 完了報告前にプロセスを再起動し、`build_info.git_commit`がHEADと一致することを断定形で記載する（未来形で締めない）。
- **完了報告の実装根拠には、コミットメッセージだけでなく実際のコミットハッシュ値を必ず併記する。**

## 注意

- 作業1〜5は依存関係があるため、必ずこの順で1タスクずつ進め、都度完了報告してから次へ進むこと。バッチ実行モードは使わない。
- 「既存afocal指標が壊れていない」という主張は、目視ではなく必ず変更前後の実測数値で裏付けること（R68で指摘された「アイレリーフ算出が模型眼内面を誤って参照する」という具体的な失敗モードを回帰テストで直接カバーすること）。
- 網膜の曲面表現（`R=-17.2mm`）は初期版では平面近似とし、対応不可の理由をR68同様に明記して次段階へ送ってよい。
