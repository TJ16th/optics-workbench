# P005/P006：`/v1/education/preview`のNaN JSONシリアライズエラー調査 指示書（Codex向け）

## 背景

R29（プリセット有効径見直し）の実施中、P005（カセグレン）・P006（双眼鏡）で`/v1/education/preview`・`/v1/trace/forward`の両方が、`ray_aiming.mode`（full/paraxial/off）を問わず一貫して以下のエラーで400を返すことが判明した。

```text
{"severity":"error","code":"optics_value_error","params":{},"message_en":"Out of range float values are not JSON compliant: nan"}
```

これはR29の作業内容（有効径調整）とは無関係の、計算結果にNaNが混入しJSONへシリアライズできていない不具合であり、優先して調査・修正する。

## 作業

0. **発生時期の切り分け（追加・優先）**：人間から「P005/P006は以前からずっと動作していなかった（未対応機能だと思っていたが、実はバグだった可能性がある）」という情報提供があった。これを踏まえ、まず以下を確認する：
   - このNaNエラーが、直近の変更（Q1〜R31のどこか）で新たに混入したものか、それとも初期実装（Phase 1-8、特にPhase 8のafocal/mirror対応時）から存在していたバグかを、`git log`・`git blame`等で該当コード箇所の変更履歴を追って特定する。
   - Phase 1-8実装報告（`doc/reports/implementation_status_phase1_8.md`）を確認し、P005（カセグレン）・P006（双眼鏡）に対する`trace_forward`・`education/preview`の基礎動作確認が、Phase 8完了時点で実際に行われていたか（テストの有無）を確認する。
   - もし初期実装から存在するバグであれば、その旨を明記し、「afocal/mirror系の基礎trace動作確認が当初から漏れていた」ことを教訓として記録する（他の未検証の組み合わせが無いか、次項の全プリセット横断スモークテストで洗い出す）。

1. **原因調査（推測で直さない）**：P005・P006それぞれについて、`/v1/trace/forward`をローカルで直接呼び出し、レスポンス生成前のPythonレベルでどの計算値がNaNになっているかを特定する（サーバーログ・デバッガ・一時的なprint等で、JSONエンコード前の中間値を確認する）。
2. NaN発生箇所の候補を確認する：
   - P005（カセグレン、ミラー系）：伝播方向反転（propagation_sign）を伴う近軸計算・実光線計算のどこかで、0除算や未定義演算が起きていないか。特に主鏡・副鏡間の中間量、near-zero denominatorになりうる箇所を確認する。
   - P006（双眼鏡、afocal系）：角倍率・射出瞳計算等、afocal系特有の計算式で、通常の焦点系（focal）と異なる分岐を通っているか確認する。無限遠像面や角度ベースの計算で、tan/除算がゼロ割りに近づく条件がないか確認する。
3. NaN発生箇所を特定した上で、根本原因（入力値の妥当性チェック不足、計算式の分岐漏れ、特殊系（ミラー/afocal）でのエッジケース未対応等）を明確にする。
4. 修正する。修正が計算ロジック自体に及ぶ場合、既存のGolden Test（P005相当のカセグレン検証値がある）に影響がないか確認する。
5. `/v1/education/preview`・`/v1/trace/forward`双方で、P005・P006が`ray_aiming.mode: full/paraxial/off`いずれでも正常なレスポンス（200、NaNを含まない）を返すことを確認する。
6. 回帰防止のテストを追加する（P005・P006を含む全プリセットに対し、education preview・trace forwardが正常応答することを確認するテスト。可能であれば全プリセット横断のスモークテストとして追加し、今後新規プリセット追加時にも自動的にカバーされるようにする）。

## 完了条件

- P005・P006の`/v1/education/preview`・`/v1/trace/forward`がNaNエラーなく正常応答する。
- NaN発生の根本原因が報告に明記されている。
- Golden Testを含む既存テストが引き続きグリーン。
- 全プリセット横断の正常応答スモークテストが追加されている。
- 完了報告前にプロセスを再起動し、`build_info.git_commit`がHEADと一致することを確認し、断定形で報告に記載する（未来形で締めない）。

## この後

本タスク完了後、R29（全プリセット有効径見直し）を再開できる。
