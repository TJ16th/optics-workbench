# R68：アフォーカル→模型眼接続の仕組み・設計調査 指示書（Codex向け）

## 背景

R34（`2026-07-11_r34_eye_model_backlog.md`）で、「アフォーカル系のアイポイントに眼球（網膜相当）光学系を接続し、結像系として評価したい」という要望を`doc/reports/issues_backlog.md`へIssueとして登録した。**実装は行っておらず、登録のみ**の状態である。

人間が実装に進みたい意向を示したが、これは単純なプリセット追加では済まず、現行の`system_type: focal`/`afocal`二択のシステムモデルに「afocal系の終端（`eye_reference`）に、別の光学系（模型眼）を接続する」という新しい仕組みが必要になる可能性が高く、R62〜R67（プリセット追加・調整が中心）より一段大きい、エンジン仕様レベルの設計判断を伴うタスクである。

R49（絞り定義の一般化検討、`2026-07-11_r49_aperture_generalization_spec_review.md`）と同じ要領で、**まず実装せずに設計調査のみを行い、変更規模の見積もりと具体的な実現方針を報告書にまとめる**。実装は本タスクの完了後、人間が別途判断する。

## 作業

### 1. 現行モデルの棚卸し

1. `doc/engine_spec.md`の該当箇所（R34報告が言及する9.2節・22章、および`system_type`・`eye_reference`関連の記述全般）を確認し、現行のafocal評価がどこで終端し、何を出力しているか（射出瞳径、アイレリーフ、角度MTF等）を整理する。
2. `eye_reference`終端の後段に、実体のある屈折面（模型眼の角膜・水晶体等）を追加接続する余地が、現行の1システム内（`surfaces`配列を単純に延長する形）で技術的に可能かどうかを、実装コード（`optics_engine/models.py`、`optics_engine/system.py`、`optics_engine/tracing.py`等）で確認する。
3. 上記が可能な場合と、`focal`/`afocal`の二択を跨ぐ新しい接続概念（システムのチェーン）が必要な場合の両方について、実現方法を具体的に記述する。

### 2. 標準模型眼の選定

1. 視覚光学分野で標準的に使われる簡易模型眼（Gullstrand簡約模型眼等、公知の光学定数を持つもの）を1つ候補として選び、その処方（曲率・厚み・屈折率、既存の`refractive`/`sensor`面種別で表現できるか）を報告書に記載する。
2. 既存プリセットの硝材・面種別の枠組みでどこまで再現できるか、できない場合は何が不足するかを整理する（実装はしない、可否の調査のみ）。

### 3. 変更規模の見積もりと設計方針

1. R49と同じ形式で、変更規模を小・中・大で分類し、根拠を示す。
2. 具体的な実現方針を1〜2案、長所・短所付きで提示する（例：「afocal系終端に模型眼面を直接追加する軽量案」と「system chainingという新概念を導入する本格案」等）。
3. 既存のafocal評価指標（射出瞳、角度MTF等）との責務の重複・矛盾が起きないかを検討する。
4. 推奨案を1つ挙げ、次段階（実装タスクとして発注する場合の作業内容）の概略を示す。

## 完了条件

- 現行モデルでの技術的な実現可否（システム内延長で足りるか、新概念が必要か）が、実装コードの参照箇所付きで具体的に示されている。
- 標準模型眼（Gullstrand等）の処方が既存の面種別でどこまで表現可能か、数値・出典とともに示されている。
- 変更規模の見積もり（小・中・大）と推奨実現方針が、報告書に明記されている。
- `doc/reports/issues_backlog.md`の該当Issue（R34登録分）を、本調査で得た設計方針で更新する（新規Issue追加は不要、既存Issueの内容更新のみ）。
- **本タスクではエンジン・UI実装は行わない。** コード変更・新規プリセット追加は対象外。

## 注意

- R49と同じく、調査・設計方針の提示までに留め、実装には進まないこと。
- 「技術的に可能」「規模は小さい」等の主張は、目視や印象ではなく、実装コード上の該当箇所を示した上で判断すること。
