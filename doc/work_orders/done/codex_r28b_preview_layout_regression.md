# R28後続：プレビュー実行時のLayout View崩れ調査 指示書（Codex向け）

## 背景

R28（P007のS1半径修正）完了後、人間が実際にブラウザで確認したところ、静的なLayout View表示（Analysisタブ等）ではS1〜S4が正しく描画されているが、**「プレビュー」を実行すると表示が崩れる**（S1〜S4が1点に潰れたように重なり、ラベルも折り重なり、光線が不自然な角度で飛ぶ）ことが判明した。近軸マーカー（H2、F'）は正しい位置に表示されており、近軸計算自体は破綻していない。

これは「プレビュー」ボタンが叩くエンドポイント（`/v1/education/preview`）と、静的表示が使うエンドポイント（`/v1/trace/forward`等）が別経路であり、R28の修正（S1半径変更）またはR27（chief/marginal ray baseline layer）の実装が、片方の経路にしか反映されていない可能性を示唆する。過去にも`/v1/trace/forward`のみ修正して`/v1/education/preview`側の対応漏れが起きた前例（education/preview paths欠落問題）がある。

あわせて、R28完了報告の末尾に「プロセス再起動と`/v1/meta build_info.git_commit`照合は、R28コミット作成後に最終応答で結果を示す」という未来形の記述が残っている。AGENTS.mdの断定形ルールに抵触するため、これも合わせて確認する。

## 作業

1. **プレビュー崩れの原因調査（推測で直さない）**：
   - P007で「プレビュー」実行時に実際に送信されるリクエスト（`/v1/education/preview`）とレスポンスを確認する。
   - レスポンスに含まれる面プロファイル・光線経路・`layout_baseline_rays`（R27で追加）のデータが、静的表示時のレスポンス（`/v1/trace/forward`）と整合しているか比較する。
   - R28で修正したS1の`radius_mm=26.0`が、`/v1/education/preview`経路でも正しく反映されているか確認する（education preview用の別キャッシュ・別コンパイル経路が存在し、そちらが古いsystem定義を参照している可能性を疑う）。
   - UI側のLayout View描画コードが、プレビュー実行時とAnalysis実行時で異なる関数・異なるデータソースを使っていないか確認する。
2. 原因を特定し修正する。
3. 修正後、P007で「プレビュー」実行時のLayout Viewが、静的表示と同様に正しく描画されることを確認する（スクリーンショット添付）。
4. 他のプリセット（P001〜P006）でも同様に、プレビュー実行時と静的表示時でLayout View描画に差異がないか横断確認する。
5. **R28完了報告の体裁修正**：プロセスを再起動し、`build_info.git_commit`がHEADと一致することを確認し、`doc/reports/2026-07-11_r28_preset_order_and_p007_layout_regression.md`に断定形で結果を追記する。
