# R78：幾何MTFグラフの周波数サンプリング密度向上 指示書（Codex向け）

## 背景

人間からUIの幾何MTFグラフが粗い（点が少なく見づらい）との指摘があった。R73・R76の記録では、MTFチャートは1 fieldあたり空間周波数`[0, 10, 20, 40, 80]`の5点のみをプロットしている（P002の場合）。これがグラフの粗さの原因である可能性が高いが、R70以降繰り返し確認してきた通り、現状は必ず実データで再確認してから対応すること。

R76作業1で、像面湾曲・周辺光量・歪曲についてはfield方向の密度を向上済み（既存の代表値は変えず、点数だけ増やす設計）。本タスクは同じ考え方をMTFの**周波数軸**へ適用する。

## 作業

1. 現状のMTF計算・APIリクエストが使っている周波数サンプル数・値を実データで確認する（`[0, 10, 20, 40, 80]`等）。
2. MTFチャート表示用に、0から現在の最大周波数（またはNyquist相当・仕様上の妥当な上限）までを、滑らかな曲線として見せるのに十分な密度（目安：20〜40点程度）でサンプリングするよう変更する。
3. 既存の5点（またはそれに相当する主要な周波数）での値が、密度向上の前後で変化しない（同じ計算式・同じ値）ことを確認する。
4. monochromatic MTF・white MTF（R73作業3で追加済み）の両モードに同様の密度向上を適用する。
5. Ray Fan、Spot Diagram等、MTF以外の解析には本変更を適用しない。
6. 周波数点数が増えることによるAPIレスポンス時間の増加が、R71で導入した30秒性能ガードに影響しないことを確認する。影響がある場合は、既定の点数を性能とのバランスで調整し、その判断根拠を報告書に明記する。
7. 修正前後のスクリーンショットを取得し、曲線が滑らかになったことを確認する。

## 完了条件

- MTFチャートの周波数サンプル点数が、修正前後で実データ・スクリーンショットにより比較され、密度が向上していることが示されている。
- 既存の主要周波数点での値が変化していないことが数値で確認されている。
- monochromatic・white両モードで一貫していることが確認されている。
- R71の30秒性能ガードへの影響が確認され、問題があれば対応（点数調整等）とその根拠が明記されている。
- 修正が近軸値・実光線追跡・MTF計算式自体に影響を与えていないことを確認している（サンプリング密度のみの変更）。
- 既存テストがグリーン。DOM構造の変更に伴うE2Eテストの更新が必要であれば行っている。
- 完了報告前にプロセスを再起動し、`build_info.git_commit`がHEADと一致することを断定形で記載する（未来形で締めない）。
- **完了報告の実装根拠には、コミットメッセージだけでなく実際のコミットハッシュ値を必ず併記する。**

## 注意

- 「点密度が向上した」「既存値は変わっていない」という主張は、目視ではなく必ず実データ・DOM値で裏付けること。
- R70・R73・R76の過去記録にある点数はあくまで参考情報であり、現状のコードを必ず再確認してから作業すること。
- 回折MTF（波動光学的MTF、R73作業6で設計調査済み）は本タスクの対象外。人間の指示により後回しとする。
