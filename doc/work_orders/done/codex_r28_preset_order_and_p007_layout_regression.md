## 2. P007 Layout View描画破綻の調査

### 背景

P007（F1.4正負2枚組、Q5で追加）で、Layout View上の「G1形状」（正メニスカス群、S1/S2の2面構成）が表示上破綻して見えるという指摘があった。あわせて、レンズの有効径境界表示が正しく機能しているか疑わしいという指摘もある。

Q1（ガラス塗り分け・有効径境界描画）・Q2（STOP/IMG記号の実寸反映）はP002・P003・P005・P006を対象に検証されており、P007（Q5で追加、Q1・Q2より後）がこれらの検証対象に含まれていたか不明。回帰確認漏れの可能性がある。

### 作業

0. **前提確認（最優先）**：P007のS1/S2それぞれの`semi_diameter_mm`の値を確認する。これが実は「バグではなく正しい描画」である可能性が高いという判断材料がある：屈折面の`semi_diameter_mm`は、最適化前は仮置き値であることが多く、S1とS2で値が大きく異なっている場合、Q1で実装したsquared edge処理（有効半径が異なる隣接面をどう結ぶか）が、その差を正直に描いた結果として「破綻して見える」形状になっている可能性がある。まずP007のS1/S2の`semi_diameter_mm`の値そのものと、その値がQ5でどう決められたか（近軸検証時の値かどうか）を確認し、これが「描画バグ」なのか「値の設計が粗いことの正直な表れ」なのかを最初に切り分けること。後者であれば、描画ロジックは修正せず、値の見直し（後述する全プリセット有効径見直しタスク）側の対象とする。

1. 実際にP007をLayout Viewで表示し、S1/S2（正メニスカス群）・S3/S4（負メニスカス群）の描画がどう破綻して見えるか、目視で確認する（可能ならスクリーンショットを取得）。
2. Q1で実装した「同一光学要素の連続する屈折面ペアを、有効径境界で閉じた領域として描く」ロジック（squared edge規約、有効半径が異なる場合の境界処理を含む）が、P007のS1/S2・S3/S4それぞれに正しく適用されているか、コードとデータの両面で確認する。
3. 具体的な確認項目：
   - S1とS2の有効半径（`semi_diameter_mm`）に差がある場合、squared edge方式または簡易端点直結方式のどちらで描かれているか、それが意図通りか。
   - ガラス領域の塗りつぶしが、S1-S2間（空気ではなくガラスで満たされている区間）に正しく適用されているか。
   - S2-STOP-S3間（空気区間）が誤って塗りつぶされていないか。
   - 「レンズ外径」という表現について、これはQ1で「有効径境界（clear aperture boundary）」と呼ぶよう用語を統一したはずの箇所である。表示されているのが有効径境界なのか、それとも別の何か（バグにより意図しない形状になっている）なのかを切り分ける。
4. 原因を特定し修正する。修正後、P007を含む全プリセット（P001〜P007）でLayout View描画の回帰確認を行う。
5. 今後同様の「新規プリセット追加時に過去の描画修正が回帰確認されない」問題を防ぐため、新規プリセット追加時のチェックリストまたは自動テストの方針を検討し、報告する（過剰な仕組み化は避け、既存のE2Eパターンに新規プリセットを機械的に追加できる程度の軽い対応でよい）。

### 完了条件

- P007のG1形状破綻の原因が特定され、修正されている。
- 修正後、P001〜P007全プリセットでLayout View描画（有効径境界・ガラス塗り分け）が正しいことを確認する。
- 「レンズ外径」という表現の実体が、有効径境界表示なのか別の問題なのかが明確になっている。
- 今後の回帰確認方針が報告されている。
- 完了報告前にプロセスを再起動し、`build_info.git_commit`がHEADと一致することを確認する（AGENTS.md規約通り）。
