# R132b：365f0fa push承認＋docs-only push恒久ルール 指示書（Codex向け）

## 承認

人間が以下を明示承認した（2026-07-16）。

1. **`git push origin master`で`365f0fa`（R132完了報告コミット、ドキュメントのみ）をpushすること**。force禁止。push後に`git rev-list --left-right --count origin/master...HEAD`が`0 0`であることを確認する。
2. **恒久ルールの新設**：今後、**ドキュメントのみのコミット（完了報告・スクリーンショット・指示書のdone移動・issues_backlog等、製品コード/テスト/CI設定/仕様正本を含まないもの）は、事前承認なしでpushしてよい**。製品コード・テスト・CI設定・仕様正本（engine_spec/ui_spec）・スキャナ設定を含むコミットのpushは従来どおり人間の明示承認を必要とする。このルールをAGENTS.mdへ追記すること（追記コミット自体はCI設定等を含まないためdocs-only扱いでpush可）。

## 補足

- R132での保守的な確認（承認範囲外と判断して停止）は正しい対応だった。本ルールはその往復コストを削減するためのもの。
- R133〜R139のキューは従来どおり：**実装コミットはpush禁止・蓄積**し、まとめて人間承認。各タスクの報告書等docs-onlyコミットは本ルールによりpush可（ただし実装コミットより先にdocsだけpushすると参照先が無い状態になるため、実装未pushのタスクの報告書pushは実装push承認まで保留してよい。判断はCodexに委ねる）。
- 本指示書の受領・実施は簡潔な報告でよい（`doc/reports/2026-07-16_r132b_docs_push_rule.md`または既存R132報告への追記）。
