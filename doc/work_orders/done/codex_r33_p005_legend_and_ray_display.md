# P005カセグレン：凡例波長色の不整合と光線経路欠落の調査 指示書（Codex向け）

## 背景

R29（有効径見直し）・R32（NaNシリアライズ修正）完了後、人間が実際にP005（カセグレン）でLayout Viewを確認したところ、2つの問題が見つかった。

1. R30で実装した凡例のうち、「波長」区分（F線・d/e線・C線）のサンプルアイコンが、いずれも同じ緑色で表示されている。R1で実装した波長色分け規約（F線=青系、d/e線=緑黄系、C線=赤系）が凡例上に正しく反映されていない。
2. M1（主鏡）〜M2（副鏡）〜IMG間の光線経路が、細い薄緑の線（density rayらしきもの）しか見えず、R27のbaseline layer（chief太実線・marginal破線2本）がほとんど視認できない。

## 作業

### 1. 凡例の波長色不整合の調査

1. R30で実装した凡例コンポーネントのコードを確認し、波長区分のサンプルアイコンがどの値を参照して色付けされているか確認する。
2. R1で実装した実際の波長色分けロジック（`wavelengthColor()`等）と、凡例側の色指定が同じ関数・同じ値を参照しているか確認する。凡例側が別途ハードコードされた色（意図せず全て同じ緑になっている等）を使っている場合、それが原因である。
3. 凡例の波長色が、実際のLayout View描画色と一致するよう修正する。

### 2. P005での光線経路表示の調査（推測で直さない）

1. P005で「プレビュー実行」した際の`/v1/education/preview`レスポンスを確認し、`metadata.layout_baseline_rays`（chief/marginal_lower/marginal_upper）が、ミラー系（propagation_sign反転を伴う）でも正しく生成されているか確認する。
2. R32の修正（`_jsonable`によるNaN→null正規化）が、ミラー系の光線経路データに意図しない影響を与えていないか確認する。特に、M1→M2間（propagation_sign反転後の区間）の座標が、null化されるべきでない値まで誤ってnull化されていないか確認する。
3. UI側のLayout View描画コードが、baseline layerの各セグメント（STOP/M2→M1、M1→M2、M2→IMG等、ミラー反射を挟む複数区間）を正しく繋いで折れ線として描画しているか確認する。density rayとbaseline rayの重なり方（線の太さ・色・z-order）で、baseline rayが実際には描かれているがdensity rayに隠れて見えにくいだけ、という可能性も確認する。
4. 原因を特定し修正する。

## 完了条件

- 凡例の波長色（F線=青系、d/e線=緑黄系、C線=赤系）が、実際のLayout View描画色と一致する。
- P005で「プレビュー実行」後、M1〜M2〜IMG間の光線経路（chief ray太実線、marginal ray破線2本）が視認できる形で描画される（スクリーンショット添付）。
- P006（双眼鏡、afocal系）でも同様に確認する。
- 既存のE2Eが壊れていないか確認し、必要な新規テスト（凡例色の値一致確認、ミラー系でのbaseline ray表示確認）を追加する。
- 完了報告前にプロセスを再起動し、`build_info.git_commit`がHEADと一致することを確認し、断定形で報告に記載する（未来形で締めない）。
