# R63：P007「明るいF値実演用」プリセットの数値乖離 原因調査 指示書（Codex向け）

## 背景

R62作業1で、P007の現行実測値（EFL≒519.6mm、F/19.68、BFL≒452.0mm）が、P007追加時（Q5、`2026-07-10_preset_fast_negative_pair.md`）の記載値（EFL 47.5mm、F/1.8、BFL 31.8mm）と大きく乖離していることが判明した。

人間・私（Claude）で数値を突き合わせたところ、EFLが約11倍（47.5→519.6mm）、F値も約11倍（1.8→19.68）と、ほぼ同じ倍率でずれているパターンが見えた。絞り径（開口）がほぼ変わらないまま焦点距離だけが伸びれば、F値も連動して同倍率で伸びるため、これは「2枚玉では明るい系が作れない」という光学的な限界ではなく、**曲率半径・間隔等のどこかの数値が、桁または倍率単位でずれている（データ側の不具合）**を示唆している、という仮説を持っている。ただしこれは推論であり、実データでの検証はしていない。

P007は正負メニスカス2枚組で「明るいF値実演用」という目的を持つプリセットであり（Q5報告）、2枚構成自体でF1.8前後を狙うことは光学的に不可能ではない（収差は残るが、本プロジェクトのプリセットは「教育用の破綻しない初期値」であり文献精密再現ではないと仕様9.1節に明記されている）。

## 作業

### 1. 現行P007の実データ確認

1. `apps/workbench-ui/src/domain/presets.ts`の現行P007定義（各面の曲率半径・間隔・材質・有効径・STOP位置）を取得する。
2. 現行データで近軸トレース（`/v1/analysis/paraxial`）を実行し、R62作業1の実測値（EFL≒519.6mm等）を再現・確認する。

### 2. Q5時点の値との比較

1. `2026-07-10_preset_fast_negative_pair.md`（Q5報告）に記載されたP007の面データ・数値（EFL 47.5mm/F1.8/BFL 31.8mm）を確認する。
2. Q5導入時のコミット（git log/blame等でP007の初出コミットを特定）における実際のP007面データを取得し、そのデータで近軸トレースを実行し、Q5報告の数値（EFL 47.5mm等）が実際に再現されるか確認する。
   - 再現される場合：Q5時点は正しかったことになるので、その後のどの変更で数値がずれたのかをgit log/blameで特定する（R28/R29の有効径調整、R41の座標修正等、P007に触れた可能性のあるタスクを候補として確認する）。
   - 再現されない場合：Q5報告自体が当時から実測値と異なっていた（報告ミス）ことになるので、その旨を確定する。

### 3. 原因の切り分けと対応

1. 上記の結果、原因が「特定の後続タスクでの意図しない数値変更（回帰）」と特定でき、かつ該当コミットを単純に見直す・戻すことで「明るいF値実演用」の意図（EFL 47.5mm前後、F1.8〜2程度）に近い値へ戻せる場合は、9.1節の数値検証規約（近軸トレース＋代表fieldの実光線追跡でケラレ無し確認）に従って再調整・凍結し、修正する。
2. 原因がより複雑（当初から意図と実装が一致していなかった、複数の変更が絡んでいる等、単純な差し戻しでは済まない）場合は、無理に自己判断で修正を進めず、原因と選択肢を報告した上で人間の判断を仰ぐ。

## 完了条件

- P007の現行実測値とQ5時点の主張値との乖離について、git上の証拠（コミットハッシュ、diff、または「Q5時点から既に乖離していた」という実測結果）に基づいた原因が報告されている。目視・推測ではなく、実際のコミット履歴とpar軸トレース結果で裏付けること。
- 原因が単純な回帰と特定でき修正した場合は、修正後の近軸トレース・実光線追跡結果（EFL・F値・ケラレ有無）を報告し、既存テストがグリーンであることを確認する。スクリーンショットを`doc/reports/screenshots/`に保存する。
- 原因が複雑で今回修正しない場合は、その理由と選択肢を明確に報告し、次の判断を人間に委ねる。
- 修正を行った場合、完了報告前にプロセスを再起動し、`build_info.git_commit`がHEADと一致することを断定形で記載する（未来形で締めない）。
- **完了報告の実装根拠には、コミットメッセージだけでなく実際のコミットハッシュ値を必ず併記する。**
