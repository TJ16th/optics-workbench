# R65フォローアップ：ui_spec.md同期のハッシュ不一致確認 指示書（Codex向け）

## 背景

R65完了報告は、Claude側`ui_spec.md`の最終SHA-256を`F4AC6AB77D5AE2464E9787895442D83191107DB3FA4B84476E3B19281FA4E9B3`と報告した。

しかし、人間（Claude側）が実際に`F:\vscode\claude\opt\doc\ui_spec.md`のSHA-256を計算したところ、`aa2285fedcc24c1960cb78c35929284c10ca791763a0618f67b44db50dd8f57b`となり、報告値と一致しない。

なお、同時に報告された`engine_spec.md`のSHA-256（`bed0c47d2af0f24544809aeb0b373ac15757384e00329a0bc9452bb6505a3415`）はClaude側の実測と完全に一致した。ui_spec.mdのみ不一致である。

Claude側で見る限り、ui_spec.mdの内容自体は最新化されている（例：9.1節が「代表的な光学系を9つ内蔵する」になっている等）ように見えるため、内容の同期は機能している可能性が高いが、ハッシュ値の不一致の原因は不明である。

## 作業

1. 現時点のCodex側正本`doc/ui_spec.md`のSHA-256を計算する。
2. 現時点のClaude側`F:\vscode\claude\opt\doc\ui_spec.md`のSHA-256を計算する（同期ログも確認する）。
3. 上記2つ、および人間が報告した値（`aa2285fe...`）、R65報告の値（`f4ac6ab7...`）の4つを比較し、現状を整理する。
4. 不一致の原因を特定する。考えられる候補（決めつけず実際に確認すること）：
   - 同期処理のタイミング（ポーリング間隔・イベント検出漏れ等）
   - 改行コード・エンコーディング・BOM等の差異（コピー処理での正規化）
   - R65完了報告作成後にui_spec.mdへ何らかの変更が加わった
   - その他
5. 原因を特定し、必要であれば同期処理を修正し、Codex側とClaude側のui_spec.mdが実際にバイト単位で一致することを再度実測確認する。

## 完了条件

- 4種類のSHA-256値（Codex側正本の現在値、Claude側の現在値、人間報告値、R65報告値）が報告書に明記され、一致・不一致の状況が整理されている。
- 不一致の原因が特定され、修正されている（または一致していることが確認され、修正不要と判明している）。
- 修正した場合、修正後にCodex側・Claude側双方のui_spec.mdのSHA-256が一致することを実測確認する。
- 本タスクはドキュメント同期の確認・修正のみであり、コード変更を伴う場合を除きpytest等の実行は対象外である。
