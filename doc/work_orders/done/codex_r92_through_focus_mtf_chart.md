# R92：デフォーカスMTF（Through-focus MTF）チャート追加 指示書（Codex向け）

## 背景

人間から新機能の要望：固定空間周波数（10 lp/mmと30 lp/mm）でのMTF値を、横軸をデフォーカス位置（焦点ずれ量）としてプロットする「デフォーカスMTF」チャートを追加したい。M（meridional）/S（sagittal）を区別し、像高（field）ごとに表示する。レイアウトは、像高ごとに別パネル（各パネル内にM@10/S@10/M@30/S@30の4本を重ねる）とすることが決定済み。

これは現行の「MTF vs 空間周波数」チャート（固定焦点位置でのradial/M/S）とは軸が異なる新種のチャートであり、`doc/engine_spec.md`・`doc/ui_spec.md`のいずれにも現状記載がない。R70以降の経緯（既存チャートの誤り発見が繰り返された）を踏まえ、実現可能性の調査・設計を先に行ってから実装する。

## 作業

### 1. 実現可能性調査・設計

1. 現行の幾何MTF計算（`analyze_geometric_mtf`、R79でMTF専用sampling 4096 rays/fieldへ分離済み）が、指定した空間周波数（10 lp/mm・30 lp/mm）でのMTF値を、焦点位置（センサー位置、またはimage plane offset）を変えながら計算できるか、既存のAPI・データ構造で確認する。
2. デフォーカスのスイープが、system再登録を伴わない軽量な経路（例：sensor Z offsetだけを変えてtraceを再実行する）で可能かを確認する。R80・R83で判明した「複数positionの評価は現状バッチ化されておらずposition数に比例して時間が増える」という制約を踏まえ、想定スイープ点数（例：21点程度）× 3 fields × 2 frequencies × M/S の合計リクエスト数で、性能が実用範囲（R71の30秒性能ガード等）に収まるかを試算・実測する。
3. デフォーカス軸の既定範囲・刻みを決定する。目安として、対象レンズのF値・主波長から求まる回折限界の焦点深度（例：`±2λF²`程度）を基準に、MTFの山と減衰が視認できる範囲（回折限界焦点深度の数倍程度）を既定値として提案する。固定物理値（例：±0.1mm）ではなく、レンズごとに意味のある範囲になるよう根拠を示して決定する。
4. 対象field（像高）は、既存の「推奨field」規約（各プリセットのcenter/70%像高/edge等、既存チャートで使われているもの）をそのまま流用する。
5. 既存のチャート規約（R76のMTF軸固定：Y軸0〜1、Q6の3パネル標準収差図、M/S線種規約が他チャートにあれば流用）との整合性を確認し、デフォーカスMTFのパネルデザイン案をまとめる。

### 2. エンジンAPI実装

1. 調査結果に基づき、既存の幾何MTF APIを拡張するか、新規endpoint（例：`/v1/analysis/mtf/through-focus`）を追加するかを決定し、実装する。
2. リクエストは、対象周波数（複数指定可、既定10/30 lp/mm）、デフォーカス範囲・点数、対象fieldを受け取り、field×frequency×defocus点ごとのM/S MTF値を返す。
3. `doc/engine_spec.md`へ、この新機能の仕様節を追加する（既存のMTFセクションの記載形式に準拠する）。

### 3. UI実装

1. Analysisタブへ、「デフォーカスMTF（Through-focus MTF）」の新しいView種別を追加する。
2. 像高ごとに別パネル、各パネル内でM@10/S@10/M@30/S@30の4系列を表示する。Y軸は0〜1固定（R76規約に準拠）、X軸はデフォーカス位置（mm）。
3. 既存チャートの配色・線種規約（M/S区別、周波数区別）と一貫性のあるデザインにする。
4. `doc/ui_spec.md`の17章へ、新View（17.11相当）として仕様を追記する。

## 完了条件

- 実現可能性調査の結果（性能試算・デフォーカス範囲決定根拠）が報告書に明記されている。
- P002等の代表プリセットで、デフォーカスMTFチャートが実際に生成され、焦点ずれ量に応じてMTFが山型に変化する物理的に妥当な形状であることが、実測値・スクリーンショットで示されている（defocus=0付近で既存の「MTF vs 周波数」チャートの10/30 lp/mm値と一致することも確認する）。
- 像高ごとに別パネル、パネル内4系列というレイアウトが実装され、スクリーンショットで確認できる。
- 性能がR71の30秒性能ガード等、既存の実用範囲内に収まることを確認している（収まらない場合は既定点数を調整し、判断根拠を明記する）。
- `doc/engine_spec.md`・`doc/ui_spec.md`双方に新機能の仕様が追記されている。
- 既存テストが全てグリーンで、新機能を固定する回帰テストが追加されている。
- 完了報告前にプロセスを再起動し、`build_info.git_commit`がHEADと一致することを断定形で記載する（未来形で締めない）。
- **完了報告の実装根拠には、コミットメッセージだけでなく実際のコミットハッシュ値を必ず併記する。**

## 注意

- 「物理的に妥当な形状」という主張は、目視だけでなく、defocus=0での値が既存MTFチャートと一致することを含めた実測で裏付けること。
- 性能懸念（R80/R83の教訓）を踏まえ、点数を増やしすぎて実用時間を超えないよう、調査段階で必ず試算してから実装すること。
