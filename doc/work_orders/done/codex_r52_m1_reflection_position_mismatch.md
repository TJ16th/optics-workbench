# R52：M1反射面の描画位置と光線の反射点のズレ調査 指示書（Codex向け）

## 背景

R51完了後、人間が実際にブラウザで確認したところ、annulus・M2サイズの見た目は大きく改善したが、**M1（主鏡）の弧の描画位置と、実際に光線が反射している位置（折れ線の頂点）がずれている**ように見える、という新たな指摘があった。実線の主光線が、M1の弧そのものよりも手前（STOP寄り）の位置で折れ線の頂点を持っているように見える。

R42では反射の「角度」（Snellの法則との整合）を数値検証し健全であることを確認したが、反射が「起きる位置」（光線経路の折れ点の座標と、M1弧の描画位置の一致）は明示的に確認していなかった。

## 作業

### 1. 現状の客観的な確認（最優先、推測で修正しない）

1. P005のP002トレース結果（`/v1/trace/forward`等）から、主光線（chief ray）の実際の経路データを取得し、各セグメントの頂点座標（STOP通過点、M1反射点、M2反射点、IMG到達点）をX,Y座標の数値として一覧化する。
2. 上記のM1反射点のX座標と、system定義上のM1面の頂点X座標（`thickness_after_mm`の累積から求まる位置）を比較する。一致しているか、ずれているか確認する。
3. Layout View描画コードで、以下2つがそれぞれ何のデータを使って描画されているか確認する：
   - M1の弧（曲率描画）：どの面のX座標・`radius_mm`を使っているか。
   - 光線経路の折れ線：どの座標データ（trace結果の頂点、または別の計算値）を使っているか。
4. 両者が異なるデータソース、または異なる座標変換を経ている場合、それが今回のズレの原因である可能性が高い。一致すべきデータが実際に一致しているか、コードレベルで確認する。

### 2. 原因の特定と修正

1. 作業1の結果を踏まえ、ズレの原因を特定する：
   - (a) 光線経路データ自体（trace結果の座標）は正しいが、Layout View描画がそれを正しく参照していない（描画のみのバグ）。
   - (b) 光線経路データ自体（trace結果の座標）が、M1面の実際の頂点位置とずれた座標を返している（光線追跡の交点計算のバグ、より深刻）。
2. (a)であれば、描画コードを修正しM1弧の位置と光線折れ点の位置を一致させる。
3. (b)であれば、M1の交点計算ロジック（ミラー系の座標変換、propagation_sign処理を含む）を確認し、修正する。この場合はGolden Testへの影響も確認する。

### 3. 検証

1. 修正後、主光線・マージナル光線の反射点が、M1の弧の描画位置と視覚的に一致することを、実際のスクリーンショットで確認する（`doc/reports/screenshots/`配下に保存、R46規約に従う）。
2. M2についても同様のズレが無いか確認する。
3. 既存テスト（Golden Test含む）に影響が無いことを確認する。

## 完了条件

- ズレの原因（描画バグか交点計算バグか）が明確に特定・報告されている。
- 修正後、M1・M2の弧の位置と光線の反射点が視覚的に一致する。
- 既存テストがグリーン。
- 完了報告前にプロセスを再起動し、`build_info.git_commit`がHEADと一致することを確認し、断定形で報告に記載する（未来形で締めない）。

## 注意

もし原因が(b)（光線追跡の交点計算自体のバグ）であった場合、これはこれまでR42で「反射角は正しい」と確認した内容とは別レイヤーの問題であり、Golden Testの座標検証（M1後-650mm等）が実際には何を検証していたのかを再確認する必要がある。決めつけず、慎重に切り分けること。
