# 解析条件field角度の仕様確認／センサーY-Z軸割当・対角長の扱い確認 指示書（Codex向け）

2件の仕様確認をまとめて扱う。実装変更は必要最小限（明らかな表示バグのみ）に留め、主眼は「現状がどうなっているか」の正確な報告とする。

## 1. 解析条件「angle」フィールドの意味確認

### 背景

人間から「解析条件パネルの角度入力欄は、どの基準の角度なのか。有限距離物体を指定した場合はどう扱われるのか」という質問があった。

### 作業

1. UI「解析条件」パネルの角度入力欄（`theta_y_deg`/`theta_z_deg`相当）が、エンジンのfield定義（仕様15章：`type: angular`は無限遠物点からの角度、`type: object_points`は`position_mm`による有限距離物点指定）のどちらに対応するUIか確認する。
2. 現在のUIから有限距離物体（`type: object_points`）を指定する手段が存在するか確認する（R9で「UI未対応」と判明していたはずだが、再確認する）。
3. 無限遠角度モードのみが実装されている場合、UIの角度入力欄のラベル・ヘルプ（glossary）が「無限遠物点からの角度である」ことを明示しているか確認する。明示されていなければ、誤解を招く表示なので改善する（ラベル文言・ツールチップの追記程度の軽微な修正に留める）。

## 2. プリセットにfield（画角）情報を持たせるべきかの検討

### 背景

人間から「プリセットごとに設計上の想定画角が違うはずだが、プリセット側にfield情報を持たせなくてよいのか」という指摘があった。

### 作業

1. 現在のプリセット定義（`presets.ts`）が、推奨field（設計時に想定した画角セット）を持っているか確認する。
2. 持っていない場合、UIの解析条件が現在どう初期化されているか（空、固定デフォルト値、前回値の保持等）を確認する。
3. プリセット切り替え時に不適切なfield角度（例：狭角レンズ用プリセットに広角時代のfield角度が残る）が残ることで生じる問題の有無を確認する。
4. 対応方針を報告する（実装はまだ行わない。方針案を提示するに留める）：
   - (a) 各プリセットに推奨fieldセットを追加し、プリセット切り替え時にfieldをその推奨値へリセットする。
   - (b) プリセットには持たせず、UI側でユーザーに都度設定させる（現状維持）。
   - (c) その他。

## 3. センサーのY/Z軸割当の確認

### 背景

人間から「長方形センサーとして、Yが短辺、Zが長辺という理解でよいか」という質問があった。

### 作業

1. エンジン仕様のsensor定義（`width_mm`/`height_mm`）が、Y軸・Z軸のどちらに対応するかを明記している箇所を確認する（仕様6.5節等）。明記が無ければ、実装（コード）上の扱いを確認する。
2. UIのプリセット定義（P001〜P007）で、実際に`width_mm`/`height_mm`がどちらの軸に割り当てられているか確認する。
3. 明記が無い、または実装と仕様の記述が食い違っている場合、統一した規約（例：Y=height（短辺想定）、Z=width（長辺想定）等）を決めて仕様書に追記することを提案する（実装変更が必要な場合は、影響範囲を報告し、本タスクでは変更せず別タスク化する）。

## 4. 対角長のプレビュー上の扱い確認

### 背景

人間から「センサー対角長は、プレビュー上でどう扱われているか」という質問があった。

### 作業

1. センサー対角長（`sqrt(width_mm^2 + height_mm^2)`相当）が、現在何らかの計算・表示（画角換算、Layout View描画スケール等）に使われているか確認する。
2. 使われていなければ、その旨を報告する（実装追加はしない）。
