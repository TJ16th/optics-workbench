# R115：スポットダイアグラムのfield別分割パネル表示 指示書（Codex向け）

## 背景

R110でスポットダイアグラムの拡大モーダル（Carbon Modal、620px幅）を実装したが、プロットが像面全域スケールの一枚絵のため、スポット（数μm〜数十μm）が像高（mm単位）に対して点にしか見えず、「小さくてよく分からない」という元の不満（R110）が拡大後も構造的に残る。人間と協議の上、**業界標準（Zemax等）のfield別分割パネル方式**への変更を決定した。

## 方針

- **compact strip側（Preview下部の小パネル）は現行の一枚方式のまま変更しない**。全体配置の把握用として有用なため。
- **拡大モーダル側をfield別グリッドへ変更する**。

## 作業

1. 拡大モーダル内を、fieldごとの分割パネル（現行3 field構成なら横並びまたは2×2グリッド）へ変更する。
   - 各パネルは**そのfieldの主光線位置（chief ray到達点）を原点とする局所座標**で描く。chief rayが取得できないfield（aiming_failed等）は重心（centroid）を原点として代用し、その旨をパネル内に小さく注記する。
   - **全パネル共通のスケール**とし、共通スケールバー（例：100μm、値はスポット最大広がりから適切に自動選択）を表示する。field間の性能比較ができることが目的のため、パネルごとの個別スケールは不可。
   - 波長色は既存の共通関数を使用（R33の教訓：表示専用の色マップ再実装は禁止）。field別のマーカー形状は分割後は冗長になるため、統一マーカーへ簡素化してよい（判断理由を報告に記載）。
2. 各パネルへ**RMSスポット半径の数値注記**を表示する。
   - 値は可能な限り既存エンジンAPI（rms_spot_radius metric等）から取得する。APIから取得できない・呼び出しが増える場合は、表示中のスポット点群からUI側で算出してよいが、その場合は「表示点群からの算出値」であることを注記し、エンジンmetricとの定義差（サンプリング依存）を報告書に明記すること。**エンジンAPI側の変更は不可**。
3. field IDと像高（またはfield角）を各パネルのタイトルに表示する。
4. i18n新規キーはja/en両方へ追加。
5. E2E：パネル数がfield数と一致すること、共通スケールバーの存在、RMS注記の表示、モーダル開閉でLayout寸法不変（R110の既存テスト維持）を固定する。
6. スクリーンショット：P002またはP004（軸外収差が見えるプリセット）で拡大モーダルの分割表示を保存する。

## 完了条件

- 拡大モーダルがfield別分割・chief ray中心局所座標・共通スケールバー・RMS注記付きで表示される。
- compact strip・既存`spot-svg` ID・export経路・数値結果・request payloadは不変。
- `npm run ci`全通過、`npm run ui:build:pseudo`成功。
- build_info一致確認、スクリーンショット保存。
