# R86：主要UI向けAPIでの「未対応入力の黙殺」パターン スポットチェック 指示書（Codex向け）

## この指示書の性質

**本タスクは監査（スポットチェック）のみを目的とし、修正は行わない。** R85で25章（最適化API）に「未対応・不正な入力を送ってもエラーにならずHTTP 200を返し、黙って無視・無効化される」という危険なパターンが横断的に見つかった。一例として、`/v1/trace/forward`の瞳分布指定（`gaussian_quadrature`/`polar`/`hexapolar`/`sobol`等）が実際には全て同じgeneric gridになる、というR85で確認済みの事例は、25章専用ではなく`/v1/trace/forward`という広く使われるcore endpointに存在する問題である。

この事実を受け、人間から「25章以外の範囲も心配だが、全面監査ではなく狭いスポットチェックで様子を見たい」との方針が示された。日常的にUIから叩かれているcore endpoint（system登録、trace、Analysis系）に対象を絞り、同種の「黙殺」パターンが他にもないかを効率よく確認する。

## 作業

以下のendpoint・パラメータについて、明らかに不正・未対応な入力を送り、①構造化エラー（4xx等）が返る②HTTP 200だが無視されて既定動作になる③HTTP 200で異常な値が返る、のいずれかを実際に確認する。全数を厳密に網羅する必要はなく、各endpointにつき2〜3個の代表的な不正入力で様子を見ればよい。

### 1. system登録・configuration系

- `POST /v1/systems/register`：存在しない材質名（例：`UNOBTANIUM`）、存在しない`surface_type`、物理的に無効な値（負の`semi_diameter_mm`等）を送った場合の挙動。
- configuration更新：存在しない`group_id`でのgroup shift、存在しない面IDでのdecenter/tilt指定の挙動。

### 2. trace・analysis系

- `POST /v1/trace/forward`・`POST /v1/analysis/*`：R85で確認済みの瞳分布名の件は再検証不要。かわりに、存在しない`ray_aiming.mode`、範囲外の波長値（例：負の波長、10000nm等）、存在しない`image_plane_policy.mode`を送った場合の挙動を確認する。
- Analysis系のmetric/view指定で、存在しないmetric名を送った場合の挙動（25.2との類似パターンがAnalysis APIにもないか）。

### 3. education/preview系

- `POST /v1/education/preview`：既知の軽量previewパスで、不正な`iris_radius_mm`（負値、系の上限を超える値）を送った場合の挙動。

### 4. 結果のまとめ

各確認について、「①構造化エラー②黙って既定動作③異常値をそのまま返す」のいずれだったかを一覧表にする。②③に該当するものは、R85と同種の危険パターンとしてリストアップする。

## 完了条件

- 上記4カテゴリのendpoint・パラメータについて、実際のAPI呼び出し結果が一覧表で示されている。
- 「黙って無視される」「異常値がそのまま返る」に該当する箇所が、あれば全て具体的なリクエスト・レスポンス例とともに報告されている。該当なしの場合もその旨明記する。
- 本タスクは監査のみであり、修正は行わない。見つかった問題の修正要否・優先度は人間とClaudeが別途判断する。
- 全数網羅は不要。効率を優先し、代表的な不正入力パターンでの様子見に留める（詳細な全数調査が必要と判断した場合はその旨提案するに留め、本タスク内では実施しない）。

## 注意

- R85で既に確認済みの25章内の問題、および瞳分布名の`/v1/trace/forward`での挙動は再調査不要。
- 深追いはせず、明らかな黙殺パターンが見つかった時点でその1件を記録し次のendpointへ進む形でよい（網羅性より効率を優先）。
