# R73：縦収差図の形状異常調査／R70残り5ギャップ解消 指示書（Codex向け）

## 背景

R72完了後、人間がUIで縦収差図（Longitudinal Aberration、P002・標準パネル）を確認したところ、依然として形状に違和感があるとのスクリーンショット報告があった。

観測されたグラフ（X軸「焦点ずれ mm」-2.73〜0.24、Y軸「瞳高 mm」-1.24〜1.24、486nm/588nm/656nmの3色）は、次の点で光学的に不自然に見える。

- 瞳高が最大（±1.24、マージナル光線）の位置で焦点ずれが小さい（0.24付近）。
- 瞳高が0付近（近軸光線）に近づくにつれて焦点ずれが最大（-2.73付近）になる。
- カーブに明確な折れ（kink）があり、単調な滑らかな弧ではなくジグザグした形状に見える。

単純な正メニスカス／両凸単玉（P002）の球面収差は、一般に近軸光線（瞳高0付近）で焦点ずれがほぼゼロ、瞳高が大きくなるほど焦点ずれが増大する滑らかな弧を描くのが典型である。観測された形状はこれと逆の傾向（瞳高0付近で焦点ずれ最大）に見え、R72で修正した「複数fieldの誤結線」とは別の要因が残っている疑いがある。**目視の印象だけで判断せず、実際の光線追跡データで検証してから結論を出すこと。**

あわせて、R70（`2026-07-13_r70_aberration_mtf_ui_inventory.md`）で報告された残り5ギャップも本タスクでまとめて解消する。

## 作業1（最優先）：縦収差図の形状異常調査・修正

1. P002について、瞳高（pupil height）と焦点ずれ（focus shift）の対応関係を、UIが描画に使っているデータとは独立に、近軸計算・実光線追跡から検証する。具体的には、瞳高0付近（近軸光線に近いサンプル）と瞳高最大付近（マージナル光線）のそれぞれで、実際の焦点面がどこにあるべきかを計算し、現在描画されている値と突き合わせる。
2. 縦収差図の基準点（焦点ずれ=0とする基準面）が何か（paraxial focus、best focus、特定波長の近軸像面等）を、実装コードとui_spec.mdの記述の両方で確認し、一致しているか確認する。基準面の選択自体に誤りがないか検証する。
3. 瞳高と焦点ずれの対応付けで、軸の反転・データの取り違え・サンプリング順序の誤りがないか、実データ（各サンプル点の瞳座標・焦点ずれ値のペア）を報告書に列挙して確認する。
4. 原因を特定し修正する。修正後、P002だけでなくP003（アクロマート、色収差補正済みのため軸上色収差カーブの形状が異なるはず）でも、期待される物理的挙動（近軸光線でほぼゼロ、周辺光線で増大する等）と整合することを確認する。
5. 修正前後のスクリーンショットと、対応する実データ（瞳高・焦点ずれのペア一覧）を報告書に示す。

## 作業2：ui_spec.md 17章への専用View仕様追記

R70・R72で確認済みの現行実装内容（Ray Fan、Longitudinal Aberration、Field Curvature、Distortion各Viewの表示軸・凡例・series構成・empty/error状態）を根拠に、`doc/ui_spec.md` 17章へ以下4つの専用セクションを追加する。

1. Ray Fan View（17.7想定）
2. Longitudinal Aberration View（17.8想定、作業1の修正後の正しい仕様を記載すること）
3. Field Curvature / M-S Image Surface View（17.9想定）
4. Distortion View（17.10想定）

各セクションは、既存の17.2〜17.6節と同じ形式（表示項目一覧）で記述する。

## 作業3：white / monochromatic MTF切替のUI接続

1. R70で判明した通り、`POST /v1/analysis/white-mtf`はエンジン実装済みだがUIが接続していない。UIにwhite/monochromatic MTF切替コントロールを追加し、white MTF APIへ接続する。
2. 凡例・軸単位が現行のmonochromatic MTF表示と混同しないよう区別する。
3. `doc/ui_spec.md` 17.5節（MTF Chart View）の該当記述を実装済みへ更新する。

## 作業4：aiming_failedの可視化

1. R70・R72で繰り返し確認された「`aiming_failed`点が描画から除外され、全点成功であるかのように見える」問題に対応する。Ray Fan・Longitudinal Aberrationパネルで、`aiming_failed`が発生した場合に、失敗点数または警告表示をUIへ追加する。
2. R59・R60で導入済みのvignetted ray可視化（gray破線＋終端マーカー）の考え方を参考にしてよいが、Analysis chartでの表現はLayout Viewとは別物のため、chart上で妥当な表現（例：失敗点数の注記、警告アイコン等）を独自に設計してよい。

## 作業5：`ray_fan_error` / `longitudinal_aberration` merit operandの実装

1. `doc/engine_spec.md`のoperand表に記載されている`ray_fan_error`・`longitudinal_aberration`が、merit evaluator（最適化オペランド）として実装されていないことがR70で判明している。既存の他operand実装を参考に、これら2つをmerit evaluatorへ実装する。
2. 単体テストを追加し、既知の光学系（例：P002）で期待される値が得られることを確認する。

## 作業6：diffraction included切替（設計調査のみ、実装は対象外）

1. `capabilities.diffraction_psf=false`であり、回折を含むPSF/MTF計算がエンジンに未実装であることがR70で判明している。これは「大」規模の変更であり、本タスクでは**実装せず、R49・R68と同じ要領で設計調査のみ**行う。
2. 現行の幾何PSF/MTF計算（`doc/engine_spec.md` 22章）に対し、回折限界PSF/MTF（波面誤差・瞳関数からのフーリエ変換等の一般的な回折光学計算）を追加する場合の変更規模を見積もる。
3. 実現方針を1〜2案、長所・短所付きで提示する。
4. 変更規模の見積もり（小・中・大）と推奨方針を報告書にまとめ、`doc/reports/issues_backlog.md`へ登録する。
