# Layout View：主光線・マージナル光線の明示的な描画 指示書（Codex向け）

## 背景

R26の調査で、現在のLayout View代表光線選択（`lower`/`center`/`upper`）は、実到達Y座標に基づく選択自体は正しいが、`grid`サンプリングの格子間隔が`samples_per_field`によって変わるため、選ばれる代表点の物理的な位置が本数設定に依存してブレることが判明した。

これはサンプリングベースの選択が抱える構造的な限界であり、選択ロジックを改善するより、**エンジンが既に定義を持つ主光線（chief ray）・マージナル光線（marginal ray）を明示的に狙って計算し、常に同じ位置に描く**方が根本的な解決になる。エンジン仕様16章（ray aiming）・14章（近軸計算）に、この2種の光線の定義とaimingの仕組みが既にある。

## 作業

1. Layout Viewの光線描画を2層に分ける：
   - **基準光線層**：各field・波長について、主光線（絞り中心を通る、厳密aiming）と、マージナル光線（絞りの上端・下端を通る、厳密aiming）を常に計算・描画する。`samples_per_field`の設定値によらず、常にこの構成（1 field・1波長あたり主光線1本＋マージナル光線2本）を描く。
   - **密度確認層**：現行の`samples_per_field`に応じたサンプリング光線（`lower`/`center`/`upper`等）を、基準光線層とは別に、既定でオン/オフ切り替え可能な形で重ねて描画する。既定はオン（後方互換）とし、オフにすると基準光線層のみが残る。
2. 基準光線層の主光線・マージナル光線は、エンジンの既存ray aiming機構（絞り中心・絞り縁を狙う厳密解）を使う。新規のエンジン側実装が必要か、既存のtrace応答（chief ray/marginal ray相当のデータが既に含まれているか）を確認し、無ければ追加する。
3. 基準光線層と密度確認層を視覚的に区別する（線の太さ・色・実線/破線等）。主光線とマージナル光線がどちらか一目で分かるようにする（例：主光線は実線でやや太め、マージナル光線は破線）。
4. P002・P003で、`samples_per_field`を複数パターン（5, 9, 15, 25）に変えても、基準光線層（主光線・マージナル光線）の描画位置が変化しないことを確認する（R26で見つかったブレが解消されていることの確認）。
5. 密度確認層のオン/オフ切り替えUIを追加する。

## 完了条件

- 主光線・マージナル光線が、`samples_per_field`の値によらず常に同じ位置に描画される。
- 基準光線層と密度確認層が視覚的に区別できる。
- 密度確認層のオン/オフが切り替えられる。
- 既存のE2E（layout view関連）が壊れていないか、必要な更新がされている。
- 完了報告前にプロセスを再起動し、`build_info.git_commit`がHEADと一致することを確認する（AGENTS.md規約通り）。

## 参考

R26の完了報告（`doc/reports/2026-07-11_r26_preview_ray_height_shift.md`）に記載の、サンプリング方式ごとの代表点安定性の違い（`fan_y`は常にY=-1/0/+1を含み安定）も、基準光線層の実装方針を検討する際の参考にしてよい。ただし本タスクでは`fan_y`への切り替えではなく、主光線・マージナル光線をray aimingで直接求める方式を優先する（サンプリング方式に依存しない、より根本的な解決のため）。
