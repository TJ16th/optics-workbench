# P0-7 タスク6 着手指示

## 対象

`doc/work_orders/active/codex_p0-7_performance_work_order.md`のタスク6（インタラクティブ性能検証用の使い捨てレイテンシハーネス）に着手する。

## 前提

- タスク0〜5は完了済み。タスク5で`profiling: true`が使えるようになっており、本タスクのハーネスはこれを活用してレイテンシ内訳を画面表示できる。
- タスク2〜4の改善で、full aiming系の体感速度は大きく改善している（例：HTTP経由のtrace preview full aimingが約26.9ms、内訳はaiming 22.6ms・trace 4ms）。

## 実施内容

指示書のタスク6に定義された内容をそのまま実施する：

- `benchmarks/latency_harness.html`を単一HTMLファイルとして作成する。
  - 絞り半径スライダーと群shift_xスライダーを置き、変更のたびに`POST /v1/education/preview`（system_id参照、aiming: paraxial、25 rays × 3 fields）を送信する。
  - 直近リクエストのend-to-endレイテンシ（ms）、直近1秒の実効fps、profiling metadata（タスク5）の段階別内訳を画面に数値表示する。
  - 応答が返る前に次のスライダー変更が起きた場合の制御（in-flight中は最新値のみ保持し、応答後に送信）を入れる。
- スコープ肥大を防ぐ制約を厳守する：ビルドシステム・npm・フレームワーク・外部JSライブラリを使わない。素のfetchとDOM操作のみ。目安200行以内。光線図などの描画はしない（数値表示のみ）。これはWorkbench UI（別仕様）の先行実装ではなく使い捨て計測治具であり、機能追加やデザイン調整を行わない。
- エンジン側にCORS許可の起動オプションが無ければ追加する（開発用途、既定off）。
- スライダーを10秒間連続操作したときの実効fpsと、profiling内訳（どの段階が支配的か）を計測して報告する。

## 作業規律の確認

- **タスク6完了後、完了報告を出してこのセッションで停止する。タスク7には進まない。**
- タスク6はWorkbench UI本体（`apps/workbench-ui/`）への機能追加ではない。`benchmarks/`配下の独立した使い捨てファイルとして作成し、Workbench UIのコードには触れないこと。

## 完了条件

- ハーネスがブラウザで動作し、連続操作時の実効fpsが計測・報告される。
- 10fps未達の場合、profiling内訳に基づく原因（エンジン計算 / シリアライズ / HTTP / キャッシュミス）の特定を報告する。10fps以上達成していれば、その旨と実測値を報告する。
