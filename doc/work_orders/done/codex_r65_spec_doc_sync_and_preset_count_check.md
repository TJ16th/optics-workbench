# R65：engine_spec.md/ui_spec.mdのクロスワークスペース同期追加／プリセット数記載の確認 指示書（Codex向け）

## 背景

R55で以下2方向の自動同期を導入し、R56でAGENTS.mdの同期（Codex側→Claude側の一方向）を追加した。

1. `doc/work_orders/active`（Claude側→Codex側）
2. `doc/reports`＋`doc/reports/screenshots`（Codex側→Claude側）
3. `AGENTS.md`（Codex側→Claude側、一方向、R56で追加）

しかし、正本の`doc/engine_spec.md`・`doc/ui_spec.md`はこの同期対象に含まれていない。Claude側はプリセット一覧・仕様内容を完了報告の評価に都度参照しているため、Codex側でこれらが更新されてもClaude側の参照コピーが古いままだと、確認・評価の精度が落ちる。実際、R62・R64でのプリセット追加・仕様更新がClaude側の`doc/ui_spec.md`に一切反映されておらず、「代表的な光学系を6つ内蔵する」という古い記述のままであることが確認された。

また、R64の完了報告に「9.1の内蔵プリセット数9件と実コード上のプリセット数が一致した」との記載があるが、P010新設後であれば実際には10件のはずであり、記載ミスの可能性がある。

## 作業

### 1. engine_spec.md/ui_spec.mdの同期追加

1. R55/R56で追加した同期スクリプト（`scripts/sync_cross_workspace_docs.ps1`）に、以下の一方向同期を追加する：
   - リポジトリ直下（または実際の配置場所）の`doc/engine_spec.md` → `F:\vscode\claude\opt\doc\engine_spec.md`
   - リポジトリ直下（または実際の配置場所）の`doc/ui_spec.md` → `F:\vscode\claude\opt\doc\ui_spec.md`
   - いずれもCodex側→Claude側の一方向のみ。Claude側からの書き戻しは行わない。
2. 同期方式はR55/R56の既存実装に合わせる：更新検出のポーリング、起動時のSHA-256照合による補完、削除非同期、同一パスへの再配置時の再同期。
3. 既存のWindowsタスクに相乗りし、多重起動・二重実行が発生しないようにする。
4. 同期ログに本追加分のイベントも記録されるようにする。
5. `AGENTS.md`の「Claude/Codexワークスペース間のドキュメント同期」節に、今回追加した同期対象を追記する。

### 2. プリセット数記載の確認・修正

1. 現在のコード上のプリセット総数を確認する（P001〜P010で全10件になっているはずである）。
2. `doc/ui_spec.md` 9.1節の「代表的な光学系を◯つ内蔵する」の記述が、実数と一致しているか確認する。一致していなければ正しい数に修正する。
3. R64完了報告の「9.1の内蔵プリセット数9件と実コード上のプリセット数が一致した」という記載が誤りだったのか、それとも別の時点の数を指していたのか（例えば作業1完了時点ではP010がまだ存在しなかった等）を確認し、本タスクの報告で明確にする。

## 完了条件

- `doc/engine_spec.md`・`doc/ui_spec.md`を更新後、`F:\vscode\claude\opt\doc\engine_spec.md`・`F:\vscode\claude\opt\doc\ui_spec.md`に反映されることを実際に検証する（R55/R56と同様、検証用の一意な変更を使った実測確認とする）。
- `doc/ui_spec.md` 9.1節のプリセット数記述が、実コード上の総数と一致していることを確認・修正済みである。
- R64報告の記載（9件）についての事実確認結果が報告に明記されている。
- 完了報告のフォーマット・検証粒度はR55/R56の完了報告に準拠する。
