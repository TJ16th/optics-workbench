# Optics Workbench UI i18n・ヘルプ実装 作業指示書（Codex向け・タスクU1〜U5）

## 前提と進め方（必読）

- 対象はUI Phase 1実装済みのリポジトリ。仕様の根拠は **UI仕様v0.3 の19.2節・27章・28.5節**、および**エンジン仕様v2.3 の26.9〜26.10節**。各タスクを渡す際に該当節を添付する。
- タスクは**番号順に1タスクずつ**実施し、完了報告後に停止する。
- U4はエンジン側のv2.3対応（/v1/metaのenumerations、エラーコード形式）が実装済みであることを前提とする。未実装の場合はモックレスポンスで先行してよいが、その旨を報告する。
- 付属ファイル `glossary.ja.json` / `glossary.en.json`（70語＋エラーカタログ10件、初稿）をリポジトリの `src/i18n/glossary/` に配置して使う。内容の改変は誤記修正を除き行わない（内容レビューは人間側の作業）。

## 共通制約

1. 既存のUIテストは常にグリーンを維持する。
2. **表示文字列のハードコード禁止**。全文字列はi18nリソース経由。エンジン由来の識別子（surface ID、metric生キー、変数キー、エラーコード）は翻訳せず生のまま扱う（仕様27.2節の翻訳境界）。
3. 小数点はロケールによらずピリオド固定。toLocaleString等のロケール依存数値整形を数値データに使わない（仕様27.3節）。
4. ツールチップはホバー限定にしない。Carbon Toggletip（クリック/フォーカス開閉、Escで閉じる）を使う（仕様27.5節）。
5. 各タスクは独立コミット。コミットメッセージにタスク番号（U1等）を含める。

## タスクU1：i18n基盤導入

### 作業

1. react-i18next を導入する。リソースは `src/i18n/locales/{ja,en}/{namespace}.json`。namespaceはビュー単位（surfaceTable, layoutView, analysis, settings, common 等）＋共有（glossary, errors, units）。
2. 言語判定：初回はブラウザ言語（ja以外はen）。設定画面に言語切替を追加し、**アプリ設定として永続化**する（Projectには保存しない）。
3. キー命名規約 `{namespace}.{view}.{要素}` をREADMEに明記する。英文キー禁止。
4. i18next-parser を導入し、「コード中で参照しているキーがリソースに存在しない」「リソースにあるが未参照」を検出するnpmスクリプト（`i18n:check`）を作り、CIに追加する。
5. 開発用の擬似ロケール（全文字列を `[!! text !!]` に伸長装飾）ビルドモードを追加する。

### 完了条件

- 言語切替が動作し、再起動後も保持される。
- `i18n:check` がCIでグリーン。
- 擬似ロケールで起動できることを確認し、スクリーンショットを報告する。

## タスクU2：Phase 1実装からの文字列抽出

### 作業

1. Phase 1で実装済みの全画面（プリセット一覧、Surface Table、Layout View、validate/register、近軸カード、raw JSON、設定）からハードコード文字列を抽出し、ja/enリソースへ移す。**現状の実装言語が日英混在の場合、その一覧を先に報告してから移行する。**
2. Carbonコンポーネントの組み込み文言（ページネーション、テーブル操作等）をロケールに応じて差し替える。
3. 数値表示を監査する：小数点がピリオド固定であること、単位（mm/µm/deg等）が翻訳されていないことをテストで固定する（18章の表示精度規約と両立）。
4. 日時表示をISO 8601保持＋表示整形に統一する。

### 完了条件

- 主要画面をja/enで切り替えたスクリーンショットを報告する。
- ハードコード文字列の残存ゼロ（`i18n:check`＋目視監査結果の報告）。
- 数値・単位・識別子の非翻訳テストがグリーン。

## タスクU3：用語集統合と3階層ヘルプ

### 作業

1. `glossary.{lang}.json` のローダーと型定義を実装する（terms / errors、schema_version検証）。
2. **①用語Toggletip**：Surface Table列ヘッダ、結果metric名、近軸量カード、解析条件の設定項目に、term_idに対応する `label` ＋ `short` を表示するToggletipを付ける。ja表示では `label (en_term)` 形式で英語術語を併記する。`formula` があれば等幅表示で添える。
3. **②ヘルプドロワー**：`long` を持つ用語のToggletipに「詳しく」リンクを付け、右ドロワーでMarkdown表示する。`see_also` はドロワー内リンクとして回遊できるようにする。
4. **③エラー解説**：19.2節（v0.3改訂）に従い、エンジンのエラー応答（code＋params＋message_en）を `errors` カタログの `message` / `action` テンプレートに展開して表示する。paramsのプレースホルダ置換（{surface_ids}, {gap_mm}等）を実装する。**未登録コードはmessage_enをそのまま表示し、console警告する。**
5. metric表示ラベルを用語集 `label` に一本化する（チャート軸・テーブル・結果カードが同一ソースを参照）。

### 完了条件

- Toggletipがキーボード（Tab→Enter/Esc）とクリックで開閉できることのテスト。
- negative_air_gap エラーがja/enそれぞれのカタログ文言で表示されるテスト（モック応答でよい）。
- 未登録コードのフォールバック動作テスト。
- ドロワーのsee_also回遊のスクリーンショット報告。

## タスクU4：カバレッジCI（/v1/meta連携）

### 前提

エンジン v2.3（/v1/meta enumerations）実装済み。未実装ならenumerationsのモックJSONで構築し、その旨を報告する。

### 作業

1. CIテストを実装する：
   - glossary ja/en のキー集合（terms・errors）が完全一致すること。
   - /v1/meta の enumerations（metrics / error_codes / warning_codes / ray_status_codes）の全項目に、対応する用語集エントリ（termsまたはerrors）が存在すること。不足項目を一覧で失敗メッセージに出す。
2. 不足が検出された場合の運用をREADMEに明記する：「エンジン側で識別子を追加したら、用語集ja/enに追記してからマージする」。

### 完了条件

- カバレッジCIジョブがグリーン。故意に1項目削って失敗することの確認（レッドテスト）も報告する。

## タスクU5：チャート・エクスポートの言語追従

### 作業

1. Plotlyの軸ラベル・凡例を用語集ラベル参照に切り替え、言語切替で再描画されるようにする。
2. SVG/PNGエクスポートダイアログに出力言語選択（既定：現在のUIロケール）を追加し、軸ラベル・注記が追従するようにする。
3. Snapshot表示が言語非依存であることを確認する：過去snapshotを開いた際、ラベルは現在ロケールで表示される（保存データには生キーのみ）テストを追加する。

### 完了条件

- ja/en両方でのチャート表示とSVGエクスポートのスクリーンショット報告。
- Snapshotの言語非依存テストがグリーン。
